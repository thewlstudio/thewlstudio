# Works·Crew 상세 본문 읽기·렌더링 점검

## 확인한 문제와 수정

- 상세 조회는 존재 여부만 확인하고 타입 선언을 믿고 클라이언트에 넘겼다. `null` 본문 행, 문자열인 목록, 객체인 문단/경력/크레딧 값은 렌더링 중 `.map`/`.split` 또는 React 자식 오류를 일으킬 수 있었다. 공유 정보는 같은 잘못된 문서를 정상 문서처럼 처리할 수 있었다.
- 서버 전용 `readPublicDetail`을 추가해 **본문과 generateMetadata가 같은 검사**를 사용한다. 기본 표시값, 본문 배열/행/중첩 목록, 실제 화면에 쓰는 문자열과 키를 확인하고 잘못된 문서는 고정된 영역 이름의 오류로 중단한다.
- 정상 문서 없음(`null`)은 기존처럼 404다. 비정상 응답과 네트워크 실패는 정상 문서/404로 위장하지 않고 기존 재조회 가능한 오류 경로로 전달한다. 공개 필터·조회 태그·캐시·주소 인코딩 규약은 바꾸지 않았다.
- 잘못된 행을 빼거나 내용을 잘라서 정상 본문처럼 만들지 않는다. 정상 원본 객체·배열·순서·추가 정보는 그대로 전달하며, 선택값/목록의 기존 누락·null·빈 배열 표시는 유지한다.

## 본문과 미지원 형식

- Works: 문단·트랙·서명·크레딧 묶음/항목·사진·영상·오디오의 화면 사용 필드를 확인한다. 공개 자유 서식은 이미 별도 방어 렌더러가 있으므로 그 정규화/링크 정책을 유지한다.
- Crew: 소개·음반 연도/트랙·경력·수상/활동·학력·자격의 중첩 자료형을 확인한다. 같은 키를 서로 다른 연도/목록에서 사용하는 것은 허용하고, 같은 표시 배열의 키 중복만 거부한다.
- 미지원 타입은 `_type`/배열 식별 경계만 확인하고 내부 내용을 추측 변환하지 않는다. 원본은 같은 객체로 클라이언트에 전달하고, 기존 렌더러의 미지원 타입 미표시 정책을 유지한다. 관리 화면의 원본 보존·명시적 전환 로직을 공개 화면에서 실행하지 않는다.
- 오디오의 사용하지 않는 예전 `tracks` 등 추가 정보도 재작성하지 않는다. 위험한 URL의 기존 비활성 표시와 자유 서식의 안전한 텍스트 표시도 유지한다.

## 화면 내부 키

- 키가 없는 예전 Works 블록은 기존에 React 키 경고를 낼 수 있어 화면 전용 식별값을 제공했다. Crew의 기존 인덱스 대체도 같은 방법으로 분리했다.
- `publicContentKey`는 실제 원본 키를 `source:` 구역, 원본 키가 없는 행의 인덱스를 `index:` 구역으로 나눠 화면 식별값만 만든다. 원본 키가 `1` 또는 `index:1`이어도 키 없는 인덱스 1과 충돌하지 않는다.
- CMS `_key`는 변경/발급/저장하지 않는다. 원본 키가 있는 항목의 화면 식별은 순서가 바뀌어도 유지된다. 키 없는 예전 항목은 인덱스에 의존하므로 완전한 영속 식별자가 생긴 것은 아니다.

## 검증

- 새 테스트 **89개**: 실제 본문/공유 서버 진입점 77개, 실제 상세 렌더러 6개, 화면 키 충돌/안정성 6개.
- 서버 테스트는 오류 분류까지 포함해 수정 전 59개 실패를 확인했다. 이는 운영 장애 건수가 아니다. SDK 조회와 하위 클라이언트만 대체하며 실제 상세 페이지·공통 검사는 실행한다.
- 실제 React/Motion/Portable Text 렌더러에서도 Works 8종·Crew 6종의 문구/순서/미디어, 미지원 형식 미변환, 위험한 URL 비활성, 키 없는 원본과 null 선택 목록을 확인한다. 테스트 사진만 단순 표시로 대체하며 네트워크/재생/실제 업로드는 하지 않는다.
- 설치된 Next.js의 generateMetadata·notFound·error 안내를 확인했다. 표시값 검사는 공유 메타데이터/JSON-LD 생성 전에 수행하며, 기존 Next 중단 신호를 가로채지 않는다.
- 전체 **5,048개 / 119개 파일**, 타입 검사·ESLint(경고 없음)·프로덕션 빌드 통과. 기존 공개 1시간 ISR과 상세 사전 생성도 유지됐다.
- 로컬 프로덕션 스모크 **41/41 통과**. 공개 상세 **11개(Works 8·Crew 3)**의 200 응답·본문 제목·OG/Twitter 제목·문서별 JSON-LD를 집계 확인했다. 문서 내용은 출력하지 않았으며 임시 서버는 종료했다.

## 범위와 한계

- 모든 CMS 스키마·사업상 의미·콘텐츠 완전성을 검사하는 것은 아니다. 알려진 렌더러의 사용 필드만 방어하며, 사용하지 않는 추가 정보나 미지원 내부 형식은 해석하지 않는다.
- 직접 클라이언트 컴포넌트에 임의 입력을 주는 외부 코드까지 안전한 변환 API로 만든 것이 아니다. 실제 공개 서버 진입점에서 검사한다. 임의 Proxy/getter의 실행 격리도 범위 밖이다.
- 운영 원본을 망가뜨리거나 실제 비공개 문서를 저장해 오류를 유발하지 않았다. 잘못된 응답은 가상 데이터로 검증한다.
- 운영 저장·업로드·환경변수·의존성·스키마·디자인·커밋·배포는 변경하지 않았다.
