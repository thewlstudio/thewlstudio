# 강사 복제 버튼의 이동 실패 점검

## 확인한 문제

- 복제 성공 뒤 `startTransition` 콜백의 이동 동기 오류를 처리하지 않았다. 복사본은 만들어졌지만 화면 안에는 복제 완료/이동 실패를 구분한 안내가 없었다.
- 복제는 재실행하면 새 문서를 하나 더 만드는 작업이다. 이동만 실패한 상태에서 원래 버튼을 다시 누르지 않고 이미 만든 복사본을 여는 경로가 없었다.
- 클라이언트는 새 ID 형식은 검사했지만 자체 속성 여부와 원본 ID와의 차이는 검사하지 않았다. 서버에는 원본 ID 응답 거부가 이미 있었으며 이번에는 클라이언트 확인도 맞췄다.
- 모의 액션·라우터에서 재현한 문제다. 실제 운영 복제나 데이터 손상을 확인한 것은 아니다.

## 반영 내용

- 이동 동기 오류는 같은 전환 콜백 안에서 처리한다. `unstable_rethrow`로 Next 제어 신호는 일반 오류로 바꾸지 않는다.
- 유효한 복제 성공이 확인된 뒤 이동 호출만 실패하면 생성된 ID를 컴포넌트 상태에 보관한다. 버튼은 “복제 완료”로 잠그고, 완료/이동 실패 안내와 “복제된 강사 열기” 링크를 표시한다. 복사본을 지우거나 자동 재복제하지 않는다.
- 링크는 기존 `GuardedLink`를 사용한다. 미저장 변경이 있으면 현재 탭 이동을 확인하며 링크를 눌러도 복제 액션은 다시 호출하지 않는다.
- 보관 상태는 원본 문서 ID에 연결한다. 컴포넌트가 유지돼도 다른 원본의 버튼을 잠그거나 이전 복사본 링크를 표시하지 않는다. 정상 이동 성공 때는 이 실패 복구 상태를 만들지 않는다.
- 성공 결과의 `newId`는 자체 속성이면서 유효한 공개 문서 ID이고 원본과 달라야 한다. 결과 불명·서버의 생성 후 갱신 실패에는 새 ID를 추측해 링크를 만들지 않는다.
- 동일 프레임 중복 클릭·전환 완료까지의 공유 잠금·늦은 응답 무시·미저장 변경 확인은 유지한다. 서버 복제 방식·비공개 생성 규칙·스키마·환경변수·의존성은 바꾸지 않았다.

설치된 Next.js의 `use-router.md`, `unstable_rethrow.md`, `link.md`의 `onNavigate` 계약을 확인했다. 라우터 호출을 이동 완료 Promise로 취급하지 않는다. 오류가 발생한 경우에만 작은 복구 링크를 추가하며 정상 화면의 디자인은 유지한다.

## 검증

새 DOM 테스트 **12개**를 추가했다.

- 이동 실패의 완료 안내·원문 미노출·버튼 잠금·복사본 링크, 링크의 미저장 취소/승인과 재복제 없음.
- 원본과 같은 새 ID·상속 ID 거부, 동일 프레임 중복 클릭, Suspense 이동 대기 중 공유 잠금 유지.
- 주소 변경 뒤 성공/실패 응답 무시 2종, 서버의 생성 후 갱신 실패 안내 유지, 비정상 결과 2종 거부, 다른 원본으로의 실패 복구 상태 유출 방지.
- 보완 전 5개가 실패했고 보완 후 통과했다. 기존 잘못된 ID·미저장 확인·전송 예외·다른 변경 작업과의 잠금/화면 이탈 테스트도 회귀 확인했다.
- 전체 **4,583개 / 107개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했으며 임시 서버는 종료했다.

## 범위와 한계

- 액션과 라우터는 모의 구현이고 React DOM·잠금·미저장 보호는 실제 코드다. 복구 링크 테스트는 Next의 현재 탭 `onNavigate` 계약을 모사하며 실제 브라우저 탐색을 수행하지 않는다.
- 운영 복제·업로드·커밋·배포 또는 인증된 브라우저 E2E는 수행하지 않았다.
- 처리하는 이동 오류는 `router.push()`의 동기 호출 오류다. 이후의 네트워크/렌더링 실패나 목적지 도착을 모두 감시하는 새 오류 경계는 아니다.
- 재복제 잠금은 성공 ID를 확인한 현재 컴포넌트 상태에 한정된다. 새로고침·다른 탭·통신 결과 불명까지 포괄하는 영구 멱등성은 아니다. 서버가 `ok: false`만 반환하면 오류 문구에서 생성 ID나 상태를 역으로 추측하지 않는다.
