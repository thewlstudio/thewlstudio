# /manage 임시저장·미리보기 설계서

목표: **"저장하면 곧바로 공개"의 부담을 줄인다.** 새 강사·Crew·작업물·연습실을 홈페이지에 내보내기 전에 진짜 화면에서 먼저 확인하고, 마음에 들면 공개한다.
범위 밖: 예약 게시, 다중 사용자 승인, 계정·권한. (아래 §6)

## 1. 현재 상태 (코드로 확인한 사실)
| 항목 | 현재 |
|---|---|
| 저장 | `client.patch(발행 문서 _id)…commit()` — 발행된 문서를 바로 고친다. `drafts.*` 문서는 쓰지 않는다. |
| 공개 여부 | 강사·Crew·Studio 공간에 `isActive`가 있다. **Works에는 없다**(삭제=휴지통만). |
| 공개 필터 | Crew는 `isActive == true`(엄격), 강사·Studio는 `!(isActive == false)`(없으면 공개). 일관되지 않다. |
| 미리보기 | 편집 화면의 "진짜 화면 보기 ↗"는 **이미 저장·공개된 내용**만 보여 준다. 비공개 항목은 공개 페이지에 나오지 않아 볼 수 없다. |
| 드래프트 모드 | `/api/draft`가 **인증 없이** `draftMode().enable()` 한다. `sanityFetch`는 드래프트 모드일 때 `SANITY_API_READ_TOKEN`(현재 미설정)으로 `previewDrafts`를 읽도록 준비돼 있다. Sanity Studio의 Presentation 도구(`sanity.config.ts`)가 이 경로를 쓴다. |
| 되돌리기 | 변경 이력(History API)과 휴지통이 있어, 실수한 저장은 복원할 수 있다. |

### 1-1. 먼저 막아야 할 보안 위험
`/api/draft`는 누구나 호출해 드래프트 모드를 켤 수 있다. 지금은 읽기 토큰이 없어 **발행된 내용만** 보이므로 피해가 없다. 그러나 이 파일의 TODO대로 `SANITY_API_READ_TOKEN`을 넣는 순간, 누구든 주소 하나로 **미발행 초안을 읽을 수 있게 된다.**
→ 어떤 미리보기 기능보다 앞서 이 경로를 잠근다(§4 P1).

## 2. 접근법 비교
| | A. Sanity `drafts.*` 문서로 임시저장 | **B. "비공개 상태"를 초안으로 쓰고, 인증된 미리보기로 비공개 항목을 본다** (권장) | C. 저장 전 입력값을 그대로 미리보기 |
|---|---|---|---|
| 무엇이 초안인가 | 발행본 옆의 별도 사본 | `isActive: false`인 발행 문서 | 저장하지 않은 폼 값 |
| 새 항목 공개 전 확인 | O | **O** | △ (저장이 없으니 새로고침하면 사라짐) |
| 공개 중인 항목을 고친 뒤 공개 전 확인 | O | **X** (저장 = 반영) | O |
| 읽기 토큰 | 필요 | **불필요** (비공개 문서도 발행 문서라 공개 API로 읽힌다) | 불필요 |
| 바꿔야 할 코드 | 저장·삭제·순서·복제·복원·이력·목록·허브 수치 **전부** | 공개 필터 통일, Works 공개 여부, 미리보기 진입·배너 | 공개 페이지 4종을 폼 값으로 렌더하는 별도 경로 |
| 위험 | 큼 (이력·복원이 `drafts.` id를 모름) | 작음 | 중간 (화면 두 벌 유지) |

**권장: B를 먼저 한다.** 실제로 가장 필요한 상황은 "새 강사·새 작품을 올리기 전에 진짜 화면으로 보기"이고, B가 읽기 토큰·`drafts.*` 없이 이를 해결한다. A는 §5의 조건이 생기면 그때 한다.

## 3. B안 상세 설계

### 3-1. 공개 여부를 4개 영역에서 같은 뜻으로
- Works에 `isActive`(boolean) 추가. **없으면 공개**로 취급한다(기존 8건은 그대로 공개). 스키마·관리 폼·목록 필터·변경 이력 비교 대상에 포함.
- 공개 필터를 한 곳(`queries.ts`)에서 만든다: `PUBLIC_FILTER = !(isActive == false) && !(trashed == true)`. Crew의 엄격한 `isActive == true`는 이 규칙으로 통일한다. **확인 완료(운영 데이터):** Crew 3건 모두 `isActive == true`라 통일해도 노출 상태가 바뀌지 않는다. 강사 7건 중 1건만 `true`, 나머지는 필드가 없는데 현행 필터가 이미 "없으면 공개"다. Studio 공간 5건은 모두 `true`.
- 관리 폼 맨 위의 "공개 상태" 선택을 4개 영역에서 같은 모양·문구로 둔다: **공개** / **비공개 (홈페이지에 안 보여요. 미리보기로만 볼 수 있어요)**.
- 새로 만들 때 기본값은 **공개**(지금과 동일). 초안으로 시작하려면 "비공개로 만들기"를 고른다.

### 3-2. 인증된 미리보기 진입
- `GET /manage/preview?to=/crew/슬러그` — `isAuthenticated()`가 아니면 로그인으로. 통과하면 Next `draftMode().enable()` 후 `sanitizeRedirectPath(to)`로 이동. 로그인 쿠키와 별개인 Next 서명 쿠키라 관리자 브라우저에서만 켜진다.
- `GET /manage/preview/end` — `draftMode().disable()` 후 관리 화면으로.
- 편집 화면의 "진짜 화면 보기 ↗"를 이 경로로 바꾼다. 문구는 "홈페이지에서 미리보기 ↗ (저장한 내용 기준)". 비공개 항목이면 "비공개 상태로 미리보기".
- 공개 페이지 쪽: 드래프트 모드일 때만 `sanityFetch`가 `$includeHidden=true`를 넘긴다. 쿼리 필터는 `(!(isActive == false) || $includeHidden == true) && !(trashed == true)`. 휴지통은 미리보기에서도 제외.
- **토큰은 쓰지 않는다.** 드래프트 모드에서도 `perspective: 'published'`를 유지하고(비공개 문서도 발행 문서이므로) `SANITY_API_READ_TOKEN` 분기는 제거하거나 비활성으로 둔다. 읽기 토큰을 나중에 도입하더라도 이 설계는 영향이 없다.
- 캐시: 드래프트 모드의 요청은 `revalidate: 0`(현행 유지). 일반 방문자는 드래프트 쿠키가 없어 캐시된 공개 내용을 그대로 받는다.
- 화면 표시: 드래프트 모드이면 공개 페이지 위에 고정 띠 "미리보기 중 · 비공개 항목도 보여요 · [미리보기 끝내기]". `noindex`를 함께 낸다. 띠는 모션 줄이기 설정을 지키고, 키보드로 닿는다.
- 정적 경로: `/crew/[slug]`, `/works/[slug]`의 `generateStaticParams`는 공개 항목만 만든다. 비공개 슬러그는 `dynamicParams`로 즉석 렌더되어야 한다. **확인 완료:** 두 페이지 모두 `dynamicParams`를 끄지 않아(기본값 true) 비공개 슬러그도 즉석 렌더된다. 구현 때는 "공개 목록에 없는 슬러그는 드래프트 모드가 아니면 404"가 유지되는지 시험으로 확인한다.
- 사이트맵·구조화 데이터·공개 목록에는 드래프트 모드와 상관없이 비공개 항목이 나오지 않는다(미리보기 쿠키가 SEO 산출물에 새지 않게).

### 3-3. 기존 `/api/draft`·`/api/disable-draft`
- **확인 완료:** `sanity.config.ts`의 Presentation 도구가 `/api/draft`를 드래프트 모드 진입점으로 쓴다. 그래서 삭제하지 않고 `next-sanity`의 `defineEnableDraftMode`(시크릿 검증, 읽기 토큰 필요)로 교체한다. 읽기 토큰이 아직 없으므로, 토큰을 발급해 환경변수에 넣기 전까지는 이 경로를 **비활성(403)** 으로 두는 것이 안전하다. Studio의 Presentation 미리보기는 그동안 쓸 수 없다. 어느 쪽이든 **무인증 `enable()`은 남기지 않는다.**

### 3-4. 초심자 안내
- 새로 만들기 화면 상단: "바로 공개할까요, 먼저 확인할까요?" 두 버튼 문구는 저장 막대의 라벨과 일치("저장하고 공개" / "비공개로 저장").
- 비공개로 저장한 뒤 토스트: "저장했어요. 홈페이지에는 아직 안 보여요. [미리보기] 로 확인해 보세요."
- 목록의 비공개 항목에 "비공개" 표시(이미 있음)와 "미리보기" 바로가기.
- 투어(`tours.ts`)의 form 투어에 "공개 상태" 단계 추가, 사용 안내(`MANAGE_GUIDE.md`, `/manage/help`)에 "미리보기" 항목 추가. 체크리스트에는 넣지 않는다.

## 4. 구현 단계와 검증
| 단계 | 내용 | 검증 |
|---|---|---|
| P1 보안 | `/api/draft` 잠금 또는 삭제, 가드 테스트(무인증 호출 거부) | 단위 테스트, 운영 스모크에 `/api/draft` 무인증 → 거부 추가 |
| P2 공개 여부 통일 | Works `isActive`, 공개 필터 단일화, 4개 영역 폼의 공개 상태 문구 통일, 이력·복원이 새 필드를 인식 | Crew 3건 현재 값 조회, 공개 페이지 노출 항목 수가 전후 동일, 쿼리 필터 가드 테스트 |
| P3 미리보기 | `/manage/preview(/end)`, 드래프트 모드 쿼리 변형, 띠, noindex, `dynamicParams` 확인 | 비공개 항목: 일반 방문 404 / 미리보기 200, 쿠키 없는 방문자에 안 보임, 사이트맵 제외, 로그인 없이 `/manage/preview` 거부 |
| P4 안내 | 새로 만들기 문구, 토스트, 투어·가이드, 목록 바로가기 | 로컬 화면 시험, 모바일 폭 |

각 단계마다 `eslint`·`tsc`·`vitest`·`build`, 로컬 시험, 별도 커밋·푸시·운영 스모크.
**운영 데이터에는 시험용 항목을 만들지 않거나, 만들면 끝난 뒤 삭제한다.**

## 5. A안(`drafts.*`)으로 넘어가는 조건
아래가 실제로 필요해질 때 다시 설계한다.
- "공개 중인 항목의 수정본"을 공개 전에 따로 확인·검토해야 한다 (예: 대표가 승인하기 전).
- 여러 운영자가 같은 항목을 동시에 고친다.
- 비용: 저장·삭제·순서·복제·복원·이력·허브 수치·목록 정렬 전부가 `drafts.` id를 알아야 하므로 B안의 약 3~4배 작업이다.

## 6. 한계 (이번 범위 밖)
- **공개 중인 항목의 수정은 저장 즉시 반영**된다. 안전망은 변경 이력·되돌리기이며, 저장 전 입력값의 즉석 미리보기는 지원하지 않는다.
- 예약 게시(특정 시각에 공개)와 외부 사람에게 만료되는 미리보기 링크 공유는 포함하지 않는다. 필요하면 서명된 만료 링크(`MANAGE_SECRET` HMAC)로 추가할 수 있다.
- 미리보기는 관리자 브라우저에서만 켜진다.
