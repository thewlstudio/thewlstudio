# 관리자 기본 텍스트·선택값 저장 검증

## 확인한 문제

- 여러 액션이 파일을 `String()`으로 변환해 텍스트로 저장하거나, 공간 텍스트처럼 잘못된 타입을 빈 값으로 취급했다. `FormData.get()`만 쓰면 중복 전송의 첫 값도 조용히 선택했다.
- 잘못된 `isActive` 값은 비공개로 추측했고, 수정에서 값이 누락되면 기본값 `true`를 적용해 기존 비공개 문서를 공개할 수 있었다.
- 강사 포트폴리오·사진 위치, Works 링크/계정, 공간 부제/설명은 누락된 입력을 비우기/기본값 요청으로 처리했다. 공간 종류와 사진 위치의 새 임의 값도 정확히 검증하지 않았다.
- 이는 모의 저장소에서 재현한 결함이다. 실제 운영에서 정보 손실이나 의도하지 않은 공개가 발생했다는 뜻은 아니다.

## 변경 사항

- 서버 전용 `manageScalarIssue`가 여섯 관리 영역의 알려진 단일 텍스트 입력을 검사한다. 제공된 필드는 **중복 없는 문자열**이어야 한다. 파일을 텍스트나 빈 문자열로 바꾸기 전에 거부한다. 기존 URL·날짜·필수값·길이·JSON 구조 검사는 유지한다.
- 수정 대상 ID·생성 주소와 본문 JSON의 중복 전송도 검사한다. 동적인 Crew 링크는 기존의 전체 행 사전 검사를 유지한다. 파일 필드 자체의 중복 처리까지 이 작업에서 변경한 것은 아니다.
- 공개 상태는 정확한 `true`/`false`, 공간 종류는 `room`/`lobby`만 받는다. 임의의 새 사진 위치는 거부한다. UI와 서버가 동일한 사진 위치 목록을 공유하며 기존 선택지·라벨·디자인은 그대로다.
- 예전 사진 위치 문자열이 이미 서버에 있으면 같은 값으로 유지하는 수정만 허용한다. 클라이언트가 임의로 다른 예전 값을 주장하거나 새 문서에 미지원 값을 넣을 수는 없다.
- 수정 시 공개 상태가 생략되면 패치하지 않는다. 강사 사진 위치·포트폴리오 주소/설명/버튼, Works 유튜브/인스타그램 값, 공간 부제/설명도 생략하면 원본을 보존한다.
- 선택 텍스트를 명시적으로 비우면 기존 삭제·기본 버튼명 규칙을 유지한다. 생성의 공개 기본값 `true`, 기본 사진 위치와 기본 공간 종류도 유지한다. 필수 텍스트 누락은 기존 필수값 검사에서 거부한다.
- 공통 공개 상태와 강사 사진 위치 선택 묶음에 포커스 목적지를 추가했다. 오류 요약이 숨은 전송 필드 대신 실제 보이는 영역으로 이동한다. 오류 뒤 입력·미저장 상태는 유지한다.
- 모든 검사는 인증 이후, 업로드·패치·생성 이전에 수행한다. 원본을 비교해야 하는 사진 위치는 서버 원본 조회 이후에 검사한다. revision 조건·캐시 갱신·기존 원본 보호는 유지한다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽고 적용했다.

## 검증

새 테스트 **234개**를 추가했다.

- 실제 저장/생성 액션 229개: 각 기본 필드·JSON·식별 입력의 파일/중복, 잘못된 선택값, 누락된 공개 상태/선택값 보존, 명시적 비우기/공개 변경, 생성 기본값, 예전 사진 위치 유지와 인증 선행. 오류 시 업로드·패치·생성·캐시 갱신 없음도 확인한다.
- 실제 조회 페이지→폼→액션 5개: 네 콘텐츠 영역의 잘못된 공개 상태와 강사 사진 위치 오류에서 원본·dirty·입력 유지, 오류 요약 클릭 후 보이는 묶음에 DOM 포커스 이동을 확인한다.
- 기존 공간 길이 테스트는 부제 삭제를 검증할 때 `subtitle=""`을 명시하도록 수정했다. 누락과 비우기를 구분하는 새 계약에 맞춘 것으로 길이 경계나 정리 기대값은 낮추지 않았다.
- 인증·외부 저장소·라우터는 모의 구현이다. 실제 CMS 저장이나 인증된 브라우저 E2E를 대신하지 않는다.

전체 **3,481개 / 94개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했으며 임시 서버는 종료했다.

공개 강사 7개·Crew 3개·Works 8개·공간 5개·공통 설정 1개를 읽기 전용으로 조회했다. 현재 문자열/불리언 기본값에 실제 스칼라 검사와 사진 위치 검사를 메모리에서 적용했으며 거부 0개였다. 이것은 모든 날짜·본문·문서의 저장 왕복 검증은 아니다. 원문·문서 ID·인증 정보는 출력하지 않았다.

## 범위와 한계

- 부분 수정과 명시적 비우기의 구분을 강화한 작업이다. 미지원 원본을 자동 복구하거나 새 필드를 추가한 것은 아니다. 지원 필드를 추가할 때 검사 정의도 함께 갱신해야 한다.
- 새 길이 제한·모든 텍스트 의미 검증·파일 필드 중복/미사용 파일 처리·서버 저장 전반의 새 동시 편집 프로토콜은 추가하지 않았다.
- 공개 디자인·스키마·환경변수·의존성은 변경하지 않았다. 운영 저장·실제 업로드·커밋·배포도 하지 않았다.
