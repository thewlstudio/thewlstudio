# 이력 복원 입력·스냅샷 경계 점검

## 확인한 문제와 기존 보호

- 이력 복원은 이미 인증·영역·고정 문서 ID·현재 버전 일치·revision 조건을 검사했다. 전체 교체/재생성이 아니라 조건부 패치를 사용하고, 현재 휴지통 상태와 순서를 유지했다.
- 시점은 `Date.parse`의 성공 여부로만 검사했다. 날짜만 있거나 시간대가 없거나 달력에 없는 날짜도 통과할 수 있었다. 모의 API가 문서를 반환하면 그대로 복원 단계까지 진행했다. 실제 Sanity API가 이런 시점을 받아 잘못 저장했다는 확인은 아니다.
- 공백뿐인 요청 버전은 쓰기 전에 결국 거부되지만 불필요한 조회가 먼저 실행됐다. 스냅샷·현재 문서의 상속된 식별 정보도 정상 문서처럼 통과했다.
- 스냅샷 응답 목록의 빈 슬롯을 문서 없음으로 바꾸거나 상속된 목록을 정상 응답으로 받아들일 수 있었다. 이 부분은 비정상 런타임 응답에 대한 방어 검사다.

## 반영 내용

- `isHistoryTime`으로 날짜·시간·시간대가 명시된 입력만 받는다. 윤년·월별 날짜·시/분/초·시간대 범위를 확인해 JS의 자동 날짜 보정에 의존하지 않는다. 소수 초와 오프셋은 원문 그대로 API에 전달한다.
- 서버 복원 액션·저장 기록 응답·지정 시점 조회가 같은 시점 검사를 사용한다. 잘못된 요청은 저장소 접근 전에 거부하고, 잘못된 기록은 일부만 골라 정상 목록처럼 표시하지 않는다.
- 소수 초를 밀리초로 잘라 기록을 합치거나 `toISOString()`으로 다시 만드는 변환은 하지 않는다. 같은 밀리초 안의 서로 다른 기록도 그대로 유지한다.
- 공백 확인 버전은 조회 전에 거부한다. 과거/현재 문서의 `_id`·`_type`·`_rev`는 자체 속성이어야 한다. 버전 문자열 자체는 보정하지 않는다.
- 스냅샷 응답의 자체 `documents` 배열과 실제 슬롯을 검사한다. 정상적인 빈 배열과 `[null]`은 기존처럼 문서 없음으로 처리한다.
- 기존 휴지통·순서 보존, 시스템 필드 제외, 과거에 없던 현재 필드의 명시적 unset, 미지원 본문·배열 키의 전체 원본 복원은 유지한다. 별도 정규화·마이그레이션·재시도·교체 쓰기는 추가하지 않는다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽었다. [Sanity History API 공식 문서](https://www.sanity.io/docs/http-reference/history)의 `time: date-time` 계약도 확인했다. 공식 설명상 시점은 문서의 `_updatedAt`이 아니라 백엔드 트랜잭션 시각을 기준으로 하므로, 스냅샷의 `_updatedAt === time` 같은 비교는 추가하지 않았다.

## 검증

새 테스트 **97개**를 추가했다.

- 공통 읽기/검사 41개: 자료형·윤년·달력·시간대 13개, 잘못된 시점 8종의 조회 전/기록 응답 거부 16개, 정상 시점 원문 전달 4개, 소수 초 기록 구분 1개, 자체 문서 식별 정보 3개, 잘못된 스냅샷 응답 2개, 정상 없음 응답 2개.
- 실제 복원 액션 56개: 잘못된 시점 8개와 여섯 영역 각각의 공백 요청 버전·과거/현재 식별 속성 6종·정밀한 시점 및 미지원 본문/배열 키 보존 8개.
- 보완 전 경계 테스트 69개가 실패하는 것을 재현했고 보완 후 통과했다. 정상 보존 테스트는 기존 계약을 다시 확인한 것이다.
- 전체 **4,530개 / 106개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했으며 임시 서버는 종료했다.

## 범위와 한계

- CMS·인증은 모의 구현이다. 실제 운영 문서 복원·업로드·커밋·배포 또는 인증된 브라우저 E2E는 수행하지 않았다. 디자인·스키마·환경변수·의존성도 변경하지 않았다.
- 프로젝트 입력을 명시적 날짜시간 형식으로 제한한 것이다. 범용 ISO 8601 파서나 윤초 지원을 새로 구현한 것은 아니다. 시간대 없는 입력을 서버 지역 시간으로 추측하지 않는다.
- 요청 시점이 현재 표시 중인 최근 25개 기록 중 하나인지 별도 API 조회로 대조하거나, 보관 기간을 늘리는 기능은 추가하지 않았다. 시점에 해당하는 원본의 존재·식별과 현재 버전 검사는 유지한다.
- 복원은 해당 시점의 문서 내용을 의도적으로 되돌리는 작업이다. 과거 참조 에셋의 존재 여부를 모두 재검사하거나 원본 내용을 현재 편집기 형식으로 재작성하지 않는다.
