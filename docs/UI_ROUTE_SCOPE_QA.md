# 공개·관리 화면 경로 구분 점검

## 확인한 문제와 수정

- Preloader·SmoothScroll·페이지 전환 템플릿은 단순 `startsWith('/manage')`/`startsWith('/admin')`로 예외 화면을 판별했다. 미리보기 안내도 같은 방식으로 `/manage`를 제외했다.
- `/management`, `/manage-help`, `/administrator`, `/admin-help`처럼 이름만 비슷한 일반 경로에도 관리자용 표시 예외가 적용됐다. 미리보기 안내는 `/manage`와 비슷한 이름에서 잘못 숨겨졌다.
- 네 곳을 이미 본문 바로가기/탐색 초점에서 사용하는 `isManagePath`·`isStudioPath`와 일치시켰다. 정확한 `/manage`·`/admin` 또는 각각 `/manage/`·`/admin/`로 시작하는 실제 하위 경로만 해당한다. 여기서 `isStudioPath`는 공개 `/studio`가 아니라 Sanity Studio의 `/admin`을 뜻한다.
- 화면 판별을 위해 경로를 추가 디코딩하거나 소문자로 바꾸지 않는다. 경로 훅이 반환한 pathname의 실제 구분자를 비교한다. 인증/리다이렉트용 주소 검증기를 바꾼 작업이 아니다.

## 유지한 정책

- `/manage`와 `/admin`의 루트·끝 슬래시·하위 화면에서는 Preloader·Lenis·페이지 전환 연출을 계속 제외한다.
- 미리보기 안내는 기존처럼 관리 화면에서 숨긴다. 다른 영역의 기존 표시 정책이나 미리보기의 서버 인증 조건은 바꾸지 않았다. 종료 링크도 부수효과를 일으키는 주소가 사전 요청되지 않도록 일반 링크로 유지한다.
- 공개 `/studio`, 동작 줄이기, Preloader의 세션별 1회 연출과 타이머/잠금 수명은 그대로 유지한다.
- 존재하지 않는 이름에 새 페이지를 만든 것이 아니다. 실제 404에서는 프레임워크가 내부 `/_not-found`를 전달할 수도 있으며, 모든 방문 URL에서 같은 경로 훅 값이 나온다고 가정하지 않는다.

## 검증

- 설치된 Next.js 16.4.3의 `use-pathname.md`를 확인했다. 쿼리를 포함한 전체 URL이 아닌 pathname을 대상으로 비교한다. 재작성/프록시와 Pages Router 호환에 관한 제약도 새로운 주소 추정 코드로 우회하지 않았다.
- 회귀 검사 31개를 추가/확장했다. 이름이 비슷한 경로, 인코딩된 구분자를 포함한 문자열, 공개 `/studio`, 실제 관리 루트·하위 경로를 실제 컴포넌트와 연결해 검사한다. 수정 전 15개 실패를 확인한 뒤 수정했다.
- Lenis 검사는 실제 엔진을 사용한다. 일반 경로에서는 엔진과 전환 래퍼가 유지되고, 실제 관리 화면에는 생성되지 않는지 확인했다. Preloader의 저장소/타이머/잠금과 미리보기 안내·종료 링크도 확인했다.
- 전체 **5,139개 / 121개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 최종 빌드의 읽기 전용 로컬 스모크 **42/42 통과**로 실제 관리 화면의 로그인 보호도 확인했다.
- 이름이 비슷한 네 주소를 로컬 서버에 직접 요청해 **4/4**가 404·일반 안내·noindex이며 로그인으로 잘못 이동하지 않는지 확인했다. 내부 경로 훅의 모든 브라우저 동작을 검증했다는 의미는 아니다. 임시 서버는 종료했다.

## 범위

- 화면 표시를 위한 분기 일관성 보완이다. 관리자 인증·권한·저장 동작이나 공개 데이터의 조회 조건을 변경하지 않았다.
- 운영 데이터·업로드·환경변수·의존성·스키마·커밋·배포는 변경하지 않았다.
