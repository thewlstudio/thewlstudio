# 일반 본문 저장·재조회 식별 키 점검

## 재현한 문제

- Works·Crew의 일반 본문은 저장할 때 객체를 다시 만든다. 공통 키 함수가 `new-` 접두사를 모두 새 임시 키로 판단해, 서버 원본에 실제로 존재하던 같은 키도 재발급했다.
- 최상위 블록/섹션뿐 아니라 트랙·크레딧 묶음/항목·음반 연도/트랙·경력·수상·활동 키도 영향을 받았다. 다른 기본 정보만 저장해도 본문의 식별자가 불필요하게 달라질 수 있었다.
- 최초 회귀 테스트 **15개 중 14개가 수정 전 실패**했다. 이미 서버 원본을 통째로 유지하던 오디오 블록의 키는 기존에도 유지됐다. 실제 운영에서 이미 손실이 발생했다는 증거는 아니다.

## 반영 내용

- 공통 `managedArrayKey`가 선택적으로 **서버가 읽은 같은 원본 배열**을 받을 수 있게 했다. 그 배열에 정확히 같은 키가 있으면 `new-` 접두사와 무관하게 원본 키를 그대로 유지한다.
- 실제 원본이 없는 새 `new-` 키·미지정 키는 기존처럼 서버가 발급한다. 원본 배열을 넘기지 않는 기존 호출의 기본 규칙도 바꾸지 않았다. 접두사가 없는 기존 문자열 키의 처리·길이·공백 규칙은 유지한다.
- 최상위는 같은 키와 같은 종류의 원본 블록/섹션을 찾는다. 다른 종류의 원본을 근거로 새 임시 키를 유지하지 않는다.
- Works는 같은 본문의 트랙, 같은 크레딧 묶음, 같은 묶음의 크레딧 항목만 원본으로 인정한다.
- Crew는 같은 섹션·연도·목록의 원본을 사용한다. 다른 연도의 트랙이나 수상/활동 반대편 목록의 키가 새 항목을 기존 항목으로 위장시키지 않도록 문맥을 분리했다.
- 새 배열 전체를 전역 검색하거나 키 문자열을 임의 정규화하지 않는다. 기존 중복 키 검사, 자료형·본문 한도 검사, 미디어/미지원 블록의 원본 참조, 인증·revision·캐시 갱신 규칙은 유지한다.
- 이번 단계는 먼저 재현된 **원본 키 재발급 문제**를 보완한 것이다. 빈 항목 제거·문구 공백 정리·일반 편집기가 지원하지 않는 추가 필드의 재구성 정책까지 임의로 바꾸지 않았다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽었다. 키 문맥에는 클라이언트가 보낸 원본 주장을 쓰지 않고, 기존 액션이 조회·확인한 서버 문서를 사용한다.

## 검증

새 테스트 **25개**를 추가했다.

- 본문 왕복·키 문맥 **23개**: Works 7종·Crew 6종의 반복 저장, 중첩 키 독립 보존, 긴/공백 원본 키, 새 임시 키 발급, 상속된 가짜 키 미인정, 최상위 종류 변경, 크레딧·연도·수상/활동 간 문맥 분리.
- 실제 조회 페이지→폼→액션→모의 저장소→새 revision 재조회 **2개**: Works 제목 및 Crew 이름을 두 번 바꿔 저장해도 최상위·중첩 본문 키와 내용 유지. 기존 조회·사진·예전 형식 테스트도 유지했다.

전체 **3,071개 / 91개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 스모크도 **37/37 통과**했다.

점검 시점의 공개 Crew **3건**, Works **8건**을 읽기 전용으로 조회해 메모리 안에서만 실제 상태 변환·payload·저장 정리 함수를 적용했다. 저장된 `new-` 본문 키는 **0개**, 저장 검증 실패 **0건**이었다. 객체의 속성 나열 순서를 정규화한 전체 본문 비교에서 값·배열 순서 변화도 **0건**이었다. 원문·식별 값·인증 정보는 출력하지 않았고 업로드/문서 쓰기는 하지 않았다.

## 범위와 한계

- 새 원본 문맥은 이번 Works·Crew 본문 호출에 적용했다. 프로젝트 모든 배열 호출의 신규/기존 식별 정책을 일괄 교체한 것이 아니다.
- 저장 시 알려진 필드를 재구성하는 기존 정책은 유지한다. 지원하지 않는 추가 필드까지 일반 편집 블록에서 모두 무손실 보존한다고 보장하지 않는다. 해당 정책은 키 문제와 분리해서 검토해야 한다.
- 후속 [본문 추가 필드 보호](MANAGE_BODY_EXTRA_FIELDS_QA.md)에서 이런 원본의 손실 가능한 재작성을 업로드·저장 전에 차단했다. 추가 필드의 자동 병합이나 편집 지원을 추가한 것은 아니다.
- 오래전 저장으로 이미 바뀐 키를 추측해 복구하거나 운영 데이터를 마이그레이션하지 않는다. 현재 공개 본문에는 이번 접두사 사례가 없었다.
- 실제 운영 저장·업로드·인증된 브라우저 E2E는 수행하지 않았다. 연결 테스트의 인증·저장소·router refresh는 모의 구현이다.
- 정상 디자인·스키마·환경변수·의존성·커밋·배포는 변경하지 않았다. 기존의 다른 작업 변경도 유지했다.
