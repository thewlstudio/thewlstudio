# 공개 오디오의 화면 숨김·재표시 수명 점검

## 확인한 문제

로딩 전환에서 React Suspense가 이전 화면을 언마운트하지 않고 숨기는 경우, 오디오의 일반 effect가 계속 살아 있었다. 숨겨진 화면의 소리와 탭 제목/파비콘 연출이 남을 수 있었고, 재생 준비 중 숨겼다 돌아오면 준비 표시나 오래된 요청의 오류가 남는 경우도 재현됐다.

## 변경

- 오디오 이벤트 연결과 정리를 실제 화면 표시 수명에 맞춘 `useLayoutEffect`로 처리한다. 숨김 때 기존 요청을 무효화하고 소리·탭 표시·파비콘 타이머를 정리한다.
- 같은 파일·같은 오디오 DOM을 다시 표시할 때 실제 일시정지 상태, 현재 길이와 위치를 읽어 화면과 맞춘다. 진행 위치는 유지하지만 자동으로 재생하지 않는다. 재생은 사용자가 다시 눌러야 한다.
- 원본 파일이 바뀌면 이전 파일의 길이/진행률을 읽어 새 파일 상태로 취급하지 않는다. 기존 source 교체 회귀 검사도 유지한다.
- 숨김으로 취소된 요청의 늦은 성공/실패는 재생을 되살리거나 새 화면의 탭 정보를 덮어쓰지 않는다. 돌아온 뒤 새로 재생한 요청도 오래된 결과로 취소하지 않는다.
- 다른 재생기가 현재 탭 표시를 소유하고 있으면 숨겨지는 재생기의 정리가 그 표시를 해제하지 않는다.

## 검증

- 설치된 Next.js 16.4.3의 `loading.md`를 확인했다. 로딩 화면은 Suspense 대체 화면이며 모든 전환이 기존 컴포넌트 언마운트와 같다고 가정하지 않는다.
- 실제 React Suspense 아래 실제 오디오 플레이어를 렌더링하는 회귀 검사 8개를 추가했다. 수정 전 5개 실패를 확인했다. 숨김 때 오디오 DOM이 여전히 연결돼 있고 재표시 때 같은 DOM을 사용함을 확인해 단순 언마운트 검사와 구분했다.
- 숨김 중 재생 중지, 재표시 후 수동 재생/위치 보존, 늦은 성공/실패, 새 요청 보호, 다른 재생기의 표시 보존과 숨김 중 준비된 메타데이터 반영을 검사한다. 미디어 메서드와 이벤트는 모의 처리한다.
- 전체 **5,167개 / 121개 파일**, 타입 검사·ESLint·프로덕션 빌드를 통과했다. 기존 StrictMode·파일 교체·일반 화면 해제·오디오 오류/재시도·곡 전환·동작 줄이기 검사도 통과했다. 최종 빌드의 읽기 전용 로컬 스모크 **42/42 통과** 후 임시 서버를 종료했다.

## 범위와 한계

- 로딩 전환에 따른 React 화면 숨김을 처리한다. 브라우저 탭을 바꾸거나 창을 최소화했다는 이유만으로 재생을 중지하는 정책을 새로 추가하지 않았다.
- 브라우저의 실제 소리 출력·모든 코덱·운영 네트워크 지연을 직접 평가한 결과는 아니다. 운영 파일을 삭제하거나 장애를 유발하지 않았다.
- 디자인·연출 문구·오디오 주소·공개 콘텐츠·업로드·환경변수·의존성·스키마·커밋·배포는 변경하지 않았다.
