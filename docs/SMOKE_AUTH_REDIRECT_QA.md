# 관리자 로그인 이동 스모크 판정 보강

## 확인한 문제

- 강사 관리 스모크는 307의 이동 대상을 확인하지 않았고, 200 응답에 특정 강사 이름 세 개가 없으면 통과했다. 빈 화면·로딩 화면·다른 이름의 관리 본문도 정상으로 오인할 수 있었다.
- 나머지 관리 경로와 미리보기 진입은 이동 주소에 `/manage/login` 문자열이 포함됐는지만 검사했다. 외부 주소·유사 경로·쿼리 안의 문자열도 통과할 수 있었다.
- 먼저 추가한 회귀 검사에서 수정 전 21개 실패를 재현했다. 이는 스모크의 판정 결함이며 운영 인증 우회를 재현한 결과가 아니다. 확인한 강사 관리 페이지는 인증 확인 후에 문서를 읽는다.

## 변경

- HTTP 307/308은 요청 대상과 출처가 같고 URL 경로가 정확히 `/manage/login`이며 사용자 정보가 없는 경우만 허용한다. 정상적인 같은 출처 절대 주소와 로그인 쿼리는 허용한다.
- 설치된 Next.js 16.4.6의 `redirect` 문서와 `make-get-server-inserted-html.js`를 확인했다. 실제 운영의 `/manage/instructors`는 HTTP 200으로 시작하지만 `__next-page-redirect` refresh meta를 보내 로그인으로 이동하므로, 200을 일괄 차단하면 안 된다.
- 200은 Next가 만드는 이동 표식·refresh 속성·0/1초 형식·정확한 로그인 대상을 함께 확인한다. script·주석·비활성 template·텍스트 속 가짜 표식, 중복 refresh/속성, 서버 오류 상태는 통과시키지 않는다. 특정 고객 이름에 의존한 조건은 제거했다.
- 관리 12개 경로에 같은 판정 함수를 사용한다. 미리보기 Route Handler는 기존처럼 HTTP 이동과 미리보기 쿠키 미발급을 확인하되 대상 판정을 강화했다. 캐시 정책·noindex·공개 상세 점검은 유지한다.

## 검증과 경계

- 관련 스모크 스크립트 회귀 검사 **63개**를 통과했다. 정상 HTTP/스트리밍 이동과 잘못된 대상·빈 본문·가짜 표식·중첩 template·중복 속성·500 응답을 확인했다.
- Node 26에서 전체 **5,233개 / 126개 파일**, 타입 검사(증분 캐시 미사용), ESLint가 통과했다. 보강한 스크립트로 현재 운영 사이트의 읽기 전용 스모크 **42/42**도 통과했다.
- HTML 판정은 Next가 생성하는 알려진 스트리밍 이동 형식용이며 일반 목적 HTML 파서나 모든 인증·정보 유출에 대한 보안 증명은 아니다. 프레임워크 출력 형식이 달라져 판별할 수 없으면 성공으로 추측하지 않고 실패한다.
- 홈페이지 디자인·실제 인증 로직·CMS 데이터는 수정하지 않았다. 스모크 응답은 비로그인 GET 요청이며 저장·삭제·복원은 실행하지 않는다. 원격 CI 결과는 로컬 검사와 별도로 확인한다.
