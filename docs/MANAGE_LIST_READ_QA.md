# 관리자 목록·휴지통 원본 읽기 점검

## 확인한 문제

- 강사·Crew·Works·공간 목록은 API 응답을 타입 선언만 믿고 사용했다. 배열이 아닌 응답은 `length`/`map()` 오류가 나고, 이름·설명에 객체가 들어오면 카드 렌더링이 실패할 수 있었다.
- 누락·중복 ID는 카드 식별과 순서 변경 대상을 혼동시킬 수 있었다. 잘못된 공개·휴지통 상태는 정상 상태처럼 해석될 수 있었다. 이는 비정상 응답에 대한 방어 문제이며, 현재 Sanity에 중복 ID 문서가 실제 존재한다는 뜻은 아니다.
- 휴지통 개수를 검사하지 않아 잘못된 응답을 숫자로 비교하거나 그대로 출력할 수 있었다.
- 목록에서 직접 호출하던 `urlFor(...).url()`이 손상된 사진 참조에 예외를 내면 정상 문서 목록도 열리지 않았다.
- 강사·Crew의 휴지통 쿼리는 `isActive`를 조회하지 않았다. 삭제 전 비공개였던 문서의 상태가 목록 필터용 데이터에서 누락될 수 있었다.

## 반영 내용

- 네 목록의 일반·휴지통 조회 결과를 `unknown`으로 받아 **목록 검사 → 카드 구성** 순서로 처리한다. 문서 종류·ID·휴지통 상태와 표시/필터/수동 정렬에 필요한 필드를 두 보기 모두 조회한다.
- 명시적 빈 배열만 정상 빈 목록으로 취급한다. `null`·`undefined`·객체·문자열 응답이나 잘못된 행을 빈 목록으로 바꾸거나 필터링해 숨기지 않는다.
- 관리 가능한 공개 문서 ID, 같은 목록 내 ID 중복, 문서 종류, 사용 중인 문자열·불리언·숫자의 자료형을 확인한다. 휴지통 개수·사진 개수는 음수가 아닌 안전한 정수여야 한다. 일반 목록에 휴지통 문서가 섞이거나 휴지통에 실제 삭제 상태가 아닌 문서가 있으면 차단한다.
- 원본을 안전하게 읽지 못하면 해당 목록과 생성·순서 변경·복원 버튼을 렌더링하지 않는다. 관리 허브 내비게이션은 유지하고 `role="alert"` 안내와 기존 `/admin` 확인 링크를 제공한다. 원본 값·문서 ID·오류 객체 대신 고정된 항목 이름만 안내한다.
- 누락/null 선택 필드, 빈 문자열, 예전 문서의 기본 공개 상태·순서 처리 등은 유지한다. 기존에 숫자로 저장된 유한한 소수 순서를 새로 금지하거나 업무상 문자열을 임의의 열거형으로 제한하지 않는다.
- Works에는 없는 수동 순서·공개 상태 규칙을 추가하지 않았다. 기존 발매일 정렬과 다른 세 목록의 공통 순서 규칙도 변경하지 않았다.
- 썸네일은 별도 서버 도우미로 만든다. SDK가 사진 URL을 만들지 못하면 해당 미리보기만 생략하고 카드·검색·상세 링크는 유지한다. 정상 참조는 기존 crop/hotspot과 112px 정사각형/56px 표시를 유지한다.
- URL을 만든 이후의 이미지 로드 실패는 기존 `CmsImage` 대체 표시를 재사용한다. 일반 사진의 의미·프레임·대체 텍스트 정책은 바꾸지 않는다. 새 에셋을 만들거나 원본 사진을 수정하지 않는다.
- 조회 예외는 기존 오류 경계로 전달한다. 목록을 안전하게 읽지 못한 상태와 실제 빈 목록을 구분하며, 통신 예외를 빈 데이터로 숨기지 않는다.

설치된 Next.js 16.4.3의 `use-server.md`와 Image 참조의 `src`·`alt`·크기/`fill` 안내를 확인했다. 인증·저장 액션·revision·공통 순서 변경 잠금·캐시 갱신 정책은 변경하지 않았다.

## 검증

새 테스트 **304개**를 추가했다.

- 목록 판별 **198개**: 네 종류의 응답·행·ID·중복·개수·상태·표시 필드·원본 불변성·고정 항목 이름 안내·기존 누락 값과 숫자 순서 호환.
- 썸네일 **14개**: 잘못된 참조의 예외 격리, 정상 참조·SDK 지원 형태, 크기·원본 경로·crop/hotspot 보존.
- 실제 목록 페이지 SSR **92개**: 일반/휴지통 정상 목록과 빈 상태, 비정상 응답·행·식별 정보·상태·개수 차단, 변경 버튼 미출력, 읽기 전용 상태, 사진 오류 격리, 조회 예외 전달, 양쪽 쿼리의 필요한 필드 포함. 저장소·일부 내비게이션·이미지·목록·변경 버튼은 모의 구현이다.

전체 **2,800개 / 75개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 스모크도 **35/35 통과**했다.

네 관리자 화면과 동일한 공개 API 쿼리를 읽기 전용으로 실행하고 실제 판별 함수와 썸네일 도우미를 적용했다. 일반 목록은 **강사 7건·Crew 3건·Works 8건·공간 5건(총 23건)**, 휴지통은 네 종류 모두 **0건**이었다. 목록·휴지통 차단 항목과 썸네일 URL 생성 실패는 모두 **0건**이었다. 개별 이미지 파일의 HTTP 응답까지 검사했다는 뜻은 아니다. 원문·문서 ID·인증 정보는 출력하지 않았고 CMS 쓰기는 하지 않았다.

## 범위와 한계

- 범위는 네 관리자 **목록·휴지통 화면의 UI 읽기 보호**다. 모든 본문 필드를 목록에서 다시 읽고 검사하지 않는다. 목록에서 정상 표시돼도 중첩 본문이 잘못됐다면 별도의 [상세 원본 검사](MANAGE_DETAIL_READ_QA.md)에서 편집을 차단할 수 있다.
- 일부 행만 조용히 누락시키지 않는 보수적 정책이다. 표시 필드 한 건이 잘못돼도 목록의 변경 동작을 열지 않으므로, 안내가 계속되면 기존 관리 도구나 개발자를 통해 원본을 확인해야 한다. 자동 복구·마이그레이션을 수행하지 않는다.
- 목록과 휴지통 개수는 기존처럼 별도 조회한다. 두 응답이 같은 시점의 트랜잭션 스냅샷이라는 보장은 추가하지 않았다. 동시 변경·순서 저장의 서버 검사와 새로고침 정책은 기존 구현을 따른다.
- 잘못된 사진 참조를 생략하거나 로드 오류에 대체 이미지를 보여도 삭제된 파일이 복구되는 것은 아니다. 정상 문서의 사진 정보를 자동으로 지우거나 교체하지 않는다.
- 날짜·설명의 업무상 정확성, 전체 사진 배열이나 본문 스키마의 완전한 무결성까지 목록 검사에서 보장하지 않는다. 날짜 문자열의 기존 안전한 표시 실패 처리는 유지한다.
- 실제 운영 CMS 저장·이미지 업로드·인증된 운영 브라우저 E2E·새 안내의 시각/스크린리더 실기 검증·커밋·배포는 하지 않았다. 정상 공개 디자인·운영 데이터·스키마·환경변수·의존성은 변경하지 않았다.
