# 공개 메뉴·본문 바로가기의 클릭 구분 점검

## 확인한 문제와 수정

- 본문 제목이 아직 준비되지 않아 ‘본문 바로가기’가 기다리는 동안, 같은 링크의 수정키 클릭 또는 기본 동작이 취소된 클릭도 기존 관찰자를 먼저 해제했다. 별도 탐색 동작 때문에 현재 탭에서 이미 요청한 초점 이동까지 사라질 수 있었다.
- `SkipLink`에서 수정키·보조 버튼·이미 취소된 클릭을 먼저 제외한다. 기존 대기를 해제/교체하는 것은 현재 탭의 일반 클릭뿐이다. 새 관찰자나 라우터 처리기를 추가하지 않았다.
- 일반 클릭으로 다시 요청하면 이전 대기는 교체하며 제목이 준비된 뒤 한 번만 이동한다. 다른 해시/경로 선택, 직접 선택한 입력의 초점 보존, 컴포넌트 해제 시 정리 등 기존 동작도 유지한다.

## 메뉴 확인

- 메뉴 링크는 이미 `onNavigate`에서만 닫기와 목적지 초점 요청을 처리한다. Ctrl/Cmd·Shift·Alt·보조 버튼 클릭으로 현재 메뉴를 닫지 않는 검사를 확장했으며 메뉴 구현은 변경하지 않았다.
- 같은 페이지 제목/섹션 이동은 퇴장과 배경 잠금 해제 뒤 완료한다. 다른 페이지 이동, 뒤로/앞으로 복원과 오래된 목적지 취소도 기존 회귀 검사를 유지한다.
- 설치된 Next.js 16.4.3의 Link 문서 중 `onNavigate`, 해시 스크롤 설명과 실제 클릭 처리의 수정키/다운로드 제외 부분을 확인했다. 새 탭의 브라우저 동작을 직접 다시 구현하지 않는다.

## 검증

- 회귀 검사 11개를 추가/확장했다. 현재 탭의 대기 중 수정키 4종·보조 버튼·취소된 클릭을 재현했고 수정 전 6개 실패를 확인했다. 일반 클릭 재요청이 한 번만 완료되는 검사와 메뉴 수정키/보조 버튼 구분 검사도 포함한다.
- React DOM과 실제 컴포넌트를 사용하고, Next 링크의 탐색 콜백 및 오버레이의 애니메이션 종료는 기존 테스트 대역으로 제어한다.
- 전체 **5,150개 / 121개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 최종 빌드의 읽기 전용 로컬 스모크는 **42/42 통과**했다. 임시 서버는 종료했다.

## 범위와 한계

- 자동 테스트에서 현재 탭의 초점/스크롤·메뉴 상태를 검증한 것이다. 운영 서버를 지연시키거나 모든 운영체제에서 실제 새 탭 생성과 단축키 동작을 직접 평가한 결과는 아니다.
- 링크 목적지·디자인·메뉴 구성·퇴장 시간·관리자 인증·데이터 조회/저장 규약은 변경하지 않았다.
- 운영 데이터·업로드·환경변수·의존성·스키마·커밋·배포는 변경하지 않았다.
