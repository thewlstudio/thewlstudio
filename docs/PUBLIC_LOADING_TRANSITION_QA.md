# 공개 로딩·오류 전환과 잠금 수명 점검

## 확인한 문제

React Suspense는 이미 표시된 화면을 로딩 안내로 대체할 때 기존 화면을 언마운트하지 않고 숨겼다가 다시 보여줄 수 있다. 기존 일반 `useEffect`는 이 숨김 동안 살아 있어, 숨겨진 메뉴/클래스 모달의 body 스크롤 잠금·본문 inert·키보드/초점 제어가 로딩 화면에도 남을 수 있었다.

실제 React Suspense와 메뉴 컴포넌트로 재현한 검사에서 overflow가 원래 값으로 돌아오지 않았고, 실제 Lenis를 연결한 잠금 검사에서도 숨겨진 소유자의 토큰이 남았다. 수정 전 두 실패를 확인했다. 모든 운영 페이지 이동에서 이 상황이 발생한다는 의미는 아니다.

## 변경

- `useBodyScrollLock`의 토큰 획득/해제를 `useLayoutEffect`로 연결한다. 숨김 때 해당 소유자의 토큰만 해제하고 다시 표시하면 재획득한다. 일반 언마운트와 StrictMode 정리도 유지한다.
- `usePublicDialog`의 배경 inert와 키보드/초점 제어도 같은 표시 수명에 연결한다. 숨겨진 대화상자가 로딩 화면의 입력을 가두거나 Escape를 가로채지 않는다. 다시 표시될 때는 본문 잠금과 대화상자 내부 초점을 복원한다.
- 포털은 부모 페이지의 숨김과 별도로 화면에 남을 수 있으므로 대화상자 포털도 함께 숨긴다. 클래스 모달은 카드뿐 아니라 배경막까지 포함하는 포털 ref를 전달한다. React가 관리하는 `display`와 충돌하지 않도록 `visibility`를 소유하며 원래 값/우선순위를 복원한다. 재표시 후 같은 DOM·열림 상태와 내부 초점을 유지한다.
- 다른 소유자의 잠금은 건드리지 않는다. 바깥의 Preloader나 다른 열린 UI가 여전히 잠금을 소유하면 body와 Lenis를 계속 멈춘다.
- 일반 메뉴/모달 닫기는 기존 `active`와 퇴장 완료 시점을 그대로 사용한다. 애니메이션 도중 조기 해제하는 변경이 아니다. 로딩 화면 디자인·문구·브랜드 연출 시간은 바꾸지 않았다.

## 검증

- 설치된 Next.js 16.4.3의 `loading.md`, `template.md`를 확인했다. 로딩 안내는 Suspense 대체 화면이며, 공유 레이아웃과 템플릿의 재생성 범위는 동일하지 않다. 매번 이전 화면이 언마운트된다고 가정하지 않는다.
- 회귀 검사 12개를 추가했다. 실제 메뉴/클래스 모달과 배경막의 숨김·재표시, 원래 visibility 값/우선순위 복원, 숨긴 소유자와 별도 소유자의 중첩 잠금, 실제 Lenis의 정지/재개를 검사한다. Suspense는 실제 React를 사용하고, 오버레이의 애니메이션 종료만 기존 테스트 대역으로 제어한다.
- Works/Crew/Class 로딩 각각을 실제 Suspense에 넣어 오류 경계 또는 404 안내로 전환했다. 로딩 상태 안내 제거, 단일 main/안내 제목, 홈 링크, 오류 원문 비노출, 불필요한 잠금 없음과 초점 정책을 검사했다.
- 전체 **5,108개 / 121개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 기존 StrictMode·중첩 토큰·퇴장 완료·동작 줄이기 검증도 통과했다. 최종 빌드의 읽기 전용 로컬 스모크는 **42/42 통과**했으며 임시 서버는 종료했다.

## 범위와 한계

- 자동 테스트는 React의 숨김/재표시 수명을 재현한 것이다. 실제 운영 서버를 일부러 지연·고장 내거나 특정 운영 URL에서 같은 장애를 유발하지 않았다.
- 음성 안내 중복 여부는 DOM의 상태 안내 개수와 제거로 검사했다. VoiceOver/NVDA의 실제 음성을 직접 듣고 평가한 결과는 아니다.
- 기존 잠금의 소유권·원래 overflow/inert 값 복원·일반 닫기 포커스 정책은 유지한다. 새 전역 감시기·타이머·라우터 패치를 추가하지 않았다.
- 운영 데이터·업로드·환경변수·의존성·스키마·커밋·배포는 변경하지 않았다.
