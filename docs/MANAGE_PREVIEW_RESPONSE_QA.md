# 미리보기 응답 캐시·리다이렉트 점검

## 확인과 변경

- 기존 로컬 프로덕션 서버에서 `/manage/preview`의 비로그인 이동과 `/api/disable-draft`의 종료 이동 모두 `Cache-Control`이 없었다. 실제 중간 캐시 저장이나 정보 유출을 재현한 것은 아니다.
- Route Handler는 레이아웃에 참여하지 않으므로 `/manage/layout.tsx`의 동적 정책만으로 해당 응답 헤더까지 보장하면 안 된다. 설치된 Next.js의 Route Handlers·NextResponse·redirect·draftMode 안내를 확인했다.
- 진입의 비로그인/로그인 분기와 종료 응답에 `private, no-store`를 명시했다. 기존 임시 이동 상태 307과 상대 `Location`은 유지하며, 쿠키는 계속 Next의 `draftMode()`로 관리한다.
- 옛 무인증 진입점 `/api/draft`는 여전히 403이며, 같은 비캐시 정책을 명시했다. 새 미리보기 인증 수단이나 읽기 토큰을 추가하지 않았다.
- 주소 검증 로직은 추가 결함이 확인되지 않아 바꾸지 않았다. 외부·역슬래시·제어 문자·정규화 뒤 이중 슬래시를 거부하고, 미리보기 진입은 정규화 뒤 관리/API/Studio 경로도 거부한다. 종료의 정상 `/manage` 복귀와 공개 URL의 인코딩·쿼리·해시는 유지한다.
- 링크는 기존 일반 `<a>`를 유지한다. Next Link 사전 로딩으로 미리보기 쿠키가 의도치 않게 켜지거나 꺼지도록 바꾸지 않았다.

## 검증

- 새 회귀 테스트 **37개**: URL 경계 24개, 인증/쿠키 실패 시 진입 중단 2개, 정상 관리 허브 복귀 1개, 스모크 검사 자체의 캐시·종료 응답 실패 검출 10개.
- 기존 진입/종료 테스트도 실제 반환 `Response`의 상태·Location·캐시 헤더를 확인하도록 수정했다. 쿠키 설정 함수는 모의 실행하므로 운영 세션을 만들지 않는다.
- 전체 **4,708개 / 111개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과.
- 로컬 프로덕션 스모크 **41/41 통과**. 기존 38개에 종료 이동/쿠키 만료·외부 이동 제한·4개 미리보기 응답의 캐시 정책 검사를 추가했다.
- 서버 프로세스에만 테스트용 관리자 설정을 주입해 별도 HTTP 검사 **3개**도 통과했다. 정상 서명 세션의 쿠키 발급, 외부 목적지 요청의 홈 이동, 잘못된 세션의 로그인 이동/쿠키 미발급을 확인했다. 이동은 따라가지 않고 쿠키 값은 출력하지 않았다. 임시 서버는 종료했다.

## 범위와 한계

- 비캐시 헤더는 이 정상 처리 응답들에 대한 정책이다. 프레임워크 자체의 모든 오류 응답이나 모든 외부 CDN 설정을 증명하는 검사는 아니다.
- URL 검증은 같은 사이트 이동 경계를 다룬다. 모든 내부 경로의 실재 여부, 중간 프록시의 임의 URL 재해석까지 보장하는 라우트 허용 목록은 아니다.
- 미리보기 쿠키의 수명과 관리자 세션 만료/로그아웃 이후의 조회 권한은 후속 [미리보기 세션 점검](MANAGE_PREVIEW_SESSION_QA.md)에서 보강했다.
- 운영 CMS 저장·업로드·환경변수 수정·커밋·배포는 하지 않았다.
