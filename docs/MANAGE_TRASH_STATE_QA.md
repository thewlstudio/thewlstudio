# 휴지통·복원 대상 상태 점검

## 확인한 문제와 기존 보호

- 삭제·복원은 이미 서버에서 조회한 `_rev`를 패치 조건으로 사용했다. 조회 후 문서가 바뀌면 409 충돌로 처리하며, 이 보호를 제거하거나 새 버전을 재조회해 덮어쓰지 않는다.
- 그러나 대상 확인에서 배열 문서·상속된 문서 식별 정보·공백뿐인 버전을 허용했다. 휴지통 상태가 문자열이나 객체인 원본도 정상 불리언으로 덮어쓸 수 있었다.
- 잘못된 원본으로 쓰기 단계까지 도달하는 것을 모의 테스트로 재현했다. 운영에서 이런 문서나 잘못된 저장이 실제 발생한 것으로 확인한 것은 아니다. 상속 속성·배열 문서 테스트는 비정상 런타임 응답에 대한 방어 검사다.

## 반영 내용

- 공통 `requireManagedDocument`는 배열이 아닌 객체와 자체 `_id`·`_type`·비공백 `_rev`를 요구한다. 정상 문서의 원본 버전 문자열은 바꾸지 않는다. 이 공통 검사는 기존 수정·복제·Studio 이동 호출부에도 적용된다.
- 휴지통 작업용 `requireManagedTrashDocument`를 추가해 강사·Crew·Works·Studio의 삭제/복원 여덟 경로에 연결했다. 원본 `trashed`는 자체 불리언 또는 기존에 허용하던 누락·undefined·null이어야 한다. 상속 값·다른 자료형은 패치 전에 원본 확인을 안내한다.
- 인증·문서 종류·공개 ID 범위 검사는 기존대로 유지한다. 대상은 한 번만 조회하고, 확인한 바로 그 `_rev`로 `{ trashed: true/false }`만 저장한다. 공개 상태·순서·본문·알 수 없는 부가 정보는 패치에 넣지 않는다.
- 이미 원하는 휴지통 상태인 정상 문서도 기존처럼 요청을 허용한다. 새 토글 동작이나 추가 확인창을 넣지 않았으며, 복원이 비공개 문서를 공개로 바꾸지도 않는다.
- 기존 저장 응답 검사·캐시 갱신·409 안내·실제 영구 삭제를 하지 않는 정책은 유지한다. 잘못된 원본에는 쓰기·성공 후 캐시 갱신을 하지 않는다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽고 서버 함수의 입력·인증 검증 원칙을 확인했다. 디자인·스키마·환경변수·의존성은 바꾸지 않았다.

## 검증

새 테스트 **117개**를 추가했다.

- 실제 삭제·복원 액션 104개: 여덟 경로 각각의 잘못된 원본 8종(공백 버전·배열 문서·상속 ID/종류/버전·문자열/객체/상속 휴지통 상태), 정상 원본 상태 4종(누락·null·false·true), 모의 409 충돌 1종.
- 공통 대상 검사의 영향 경로 13개: 네 영역의 수정·삭제·복원과 강사 복제가 공백 버전에서 업로드/저장/성공 캐시 갱신을 하지 않는지 확인한다.
- 보완 전 잘못된 원본 테스트 64개가 실패하는 것을 확인했다. 나머지 정상 상태·충돌 테스트는 기존 계약의 회귀 검사다. 오류 응답에 원본 객체의 내용을 노출하지 않는 것도 검사한다.
- 원본 불변성·플래그 한 개만 패치·조회 1회·확인한 버전 조건·추가 재시도 없음도 확인했다. 409는 모의 응답이며 실제 CMS의 동시 저장을 실행한 테스트는 아니다.
- 전체 **4,387개 / 104개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했으며 임시 서버는 종료했다.

## 범위와 한계

- CMS와 인증은 모의 구현이다. 운영 문서 삭제·복원·업로드·커밋·배포 또는 인증된 브라우저 E2E는 수행하지 않았다.
- 이 보호의 충돌 범위는 서버 조회부터 패치까지다. 오래 열린 브라우저가 처음 본 버전을 새로 전달하거나, 다른 브라우저/Studio의 모든 작업을 상호 배제하는 기능을 추가하지 않았다.
- 같은 상태를 다시 요청해도 패치/캐시 갱신을 생략하는 새 최적화는 넣지 않았다. 정상 반복 요청을 허용한다는 뜻이지 요청 중복 방지 프로토콜을 새로 구현했다는 뜻은 아니다.
- 휴지통 상태 자료형이 손상된 원본은 자동 교정하지 않는다. `/admin`에서 확인해야 한다. 내용을 복원하는 변경 이력 기능과 고정 ID 설정 문서의 읽기 정책은 이번 변경 범위가 아니다.
