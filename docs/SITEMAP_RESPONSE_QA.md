# 사이트맵 수정일·비정상 조회 응답 점검

## 확인한 문제와 수정

- 고정 페이지 6곳의 `lastModified: new Date()`는 콘텐츠 수정일이 아니라 사이트맵 생성 시각이었다. 실제 변경 시점을 신뢰할 근거가 없어 이 날짜만 생략했다. URL·우선순위·변경 빈도는 유지하며, 최신 날짜나 배포 시각으로 대체하지 않았다.
- 상세 항목은 기존 CMS `_updatedAt`을 사용하되, 단순 `new Date()`의 관대한 해석을 그대로 믿지 않는다. 날짜만 있는 `YYYY-MM-DD` 또는 초·시간대가 명시된 날짜/시간만 받으며, 실제 달력·윤년·시간 범위도 검사한다. 2월 30일 자동 보정·연도만 있는 값·지역 시각 추측·24시 이월 등은 제외한다.
- 잘못된 수정일은 URL을 삭제할 이유가 아니므로 날짜만 생략한다. 정상 날짜는 기존 UTC `Date` 출력 방식을 유지한다. 소수 초의 밀리초 이하 절삭도 기존 방식과 같으며 원본 CMS는 수정하지 않는다.
- 기존 `Promise.allSettled`는 요청이 거절된 경우만 격리했다. 성공 응답이 배열이 아니거나 배열 안에 `null`/빈 슬롯이 있으면 전체 사이트맵 생성이 실패할 수 있었다. SDK 응답 타입을 `unknown`으로 받아 실제 목록/행을 확인하도록 수정했다.
- 비정상 목록은 해당 영역만 제외한다. 비정상 행은 그 행만 제외하고 앞뒤 정상 행과 다른 영역·고정 경로를 유지한다. 슬러그 검증·단일 인코딩·중복 제거 정책은 그대로다. 상속된 값은 원본 slug/수정일로 인정하지 않는다.
- 정상 빈 배열과 실패를 구분한다. 잘못된 목록/행/날짜는 영역과 오류 개수만 보고하며 원본 문서 내용은 로그에 넣지 않는다.

## 기준 문서

- 설치된 Next.js의 `sitemap.md` 전체를 확인했다. `lastModified`는 선택 항목이므로 확인할 수 없는 날짜를 만들어 넣을 필요가 없다.
- [Sitemaps 프로토콜](https://www.sitemaps.org/protocol.html)은 수정일을 사이트맵 생성일이 아닌 연결 페이지의 실제 변경일로 명시한다.
- [Google의 사이트맵 안내](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)는 검증 가능하고 일관되게 정확한 수정일을 사용하도록 설명한다. 이번 수정은 검색 순위 상승을 보장하는 작업이 아니다.

## 검증

- 새 회귀 테스트 **61개**. 수정 전 45개 실패를 확인하고 수정 후 모두 통과했다.
- 수정일 출처·생성 시각 독립성 2개, 잘못된/없는 날짜의 URL 유지 20개, 정상 날짜·윤년·소수 초·오프셋 유지 5개.
- 두 영역의 잘못된 목록·행·상속값·빈 슬롯 격리 32개, 정상 빈 목록과 두 요청 동시 실패 구분 2개.
- 기존 상세 주소·공개 노출·사이트맵 실패 격리 회귀 테스트도 통과했다. 테스트는 SDK 조회와 오류 보고만 대체하며 CMS 데이터는 변경하지 않는다.
- 전체 **4,831개 / 114개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 공개 1시간 ISR과 사이트맵 24시간 설정을 유지했다.
- 실제 로컬 프로덕션 스모크 **41/41 통과**. XML 집계에서 고정 페이지 **6개 날짜 생략**, 상세 **11개 CMS 수정일 유지**, URL 중복 없음·반복 요청 XML 동일함을 확인했다. 확인용 서버는 종료했다.

## 유지한 정책과 한계

- 공개 항목만 사이트맵에 포함하며 관리자 미리보기 상태와 무관하다. 24시간 재검증과 관리자 변경 시 `/sitemap.xml` 갱신 정책은 바꾸지 않았다.
- 한 영역이 실패해도 다른 영역을 제공하는 기존 부분 성공 정책을 유지한다. 모든 동적 조회가 실패하면 고정 경로만 반환하며 오류를 보고한다. 실패 시의 부분 사이트맵도 기존 재검증 정책을 따르므로, 마지막 정상 결과의 별도 영구 보관이나 새 자동 재시도 기능을 추가한 것은 아니다.
- `_updatedAt`은 해당 CMS 문서의 시각이며, 공통 레이아웃 코드·이미지 에셋·외부 연동 변경을 모두 합친 페이지 전체 수정일은 아니다. 고정 페이지 수정일을 그 문서 날짜로 추측하지 않았다.
- 실제 Sanity 서버에 일부러 오류를 일으키거나 운영 문서를 망가뜨려 시험하지 않았다. 비정상 응답 경계는 가상 응답으로 검증한다.
- 환경변수·의존성·스키마·운영 저장·업로드·커밋·배포는 변경하지 않았다.
