# 일반 삭제·휴지통 복원의 화면 처리 점검

## 확인한 문제

- 네 삭제 버튼은 목록 이동 전에 성공/되돌리기 알림을 예약했다. 이동 호출이 실패해도 이번 작업의 알림이 저장소에 남을 수 있었다.
- 공통 복원 버튼과 삭제 알림의 되돌리기는 새로고침 호출 전에 성공 알림을 표시했다. 새로고침 실패를 복원 완료와 구분해 안내하지 못했다.
- `startTransition` 콜백 안의 라우터 동기 오류를 처리하지 않아 화면 안 안내 대신 React 오류 경로로 전달되는 것을 모의 테스트에서 재현했다. 서버 데이터가 되돌려지거나 운영에서 실제 문제가 발생했다고 확인한 것은 아니다.

## 반영 내용

- 강사·Crew·Works·Studio 삭제 버튼에 이전 이력 복원 버튼에서 확인한 패턴을 적용했다. 이동 호출 오류는 같은 전환 콜백 안에서 처리한다.
- 삭제 응답이 성공으로 확인됐는데 이동 호출이 실패하면 “휴지통으로 옮겼지만 목록 화면을 열지 못했어요”라고 안내한다. 이번 작업의 성공/되돌리기 알림을 새로 예약하거나 삭제를 다시 보내지 않는다.
- 공통 복원 버튼은 refresh 동기 오류 시 복원 완료·화면 갱신 실패를 필드 옆 오류로 구분한다. 삭제 알림의 되돌리기도 같은 내용을 안내 알림으로 표시하고, 새 되돌리기 버튼은 만들지 않는다.
- 이동/새로고침 호출이 동기 오류 없이 반환된 뒤에만 기존 성공 알림을 예약/표시한다. 정상 삭제 알림의 원래 영역·문서 ID·되돌리기 기능은 유지한다.
- `unstable_rethrow`로 Next 제어 신호를 일반 오류 안내로 바꾸지 않는다. 서버가 반환한 결과 불명·확인된 변경 후 캐시 갱신 실패도 기존 공통 액션 검사와 함께 그대로 안내한다.
- 공유 잠금·동일 프레임 중복 요청 차단·대기 중 Escape/취소 차단·현재 주소 확인·미저장 변경 확인·포커스 복원은 유지한다. 네 폼을 범용 컴포넌트로 재작성하거나 별도 잠금/재시도 체계를 추가하지 않았다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/use-router.md`와 `unstable_rethrow.md`를 읽었다. 라우터 호출을 이동/새로고침 완료 Promise로 취급하지 않는다.

## 검증

새 DOM 테스트 **24개**를 추가했다.

- 네 삭제 버튼 각각 4개: 이동 동기 오류·이동 후 알림 예약 순서·서버 캐시 실패 안내 보존·Suspense 이동 대기 중 잠금 유지. 합계 16개.
- 공통 복원 버튼 3개: refresh 동기 오류·refresh 후 성공 알림 순서·Suspense 대기 중 잠금 유지.
- 삭제 알림 되돌리기 5개: 네 영역의 refresh 동기 오류 안내·성공 메시지/재시도 없음, 공통 Suspense 대기 중 잠금 유지.
- 보완 전 14개가 실패했고 보완 후 통과했다. 기존 통신 예외·확인 취소·미저장 변경·중복 클릭·포커스 복원과 다른 작업/늦은 응답의 공유 잠금 테스트도 회귀 확인했다.
- 전체 **4,571개 / 106개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했으며 임시 서버는 종료했다.

## 범위와 한계

- 액션과 라우터는 모의 구현이다. 삭제/공통 복원 버튼 테스트는 알림도 모의 처리하고, 알림 되돌리기 테스트는 실제 `ToastProvider`를 사용한다. React DOM과 잠금 훅은 실제 코드다.
- 운영 데이터 저장·복원·업로드·커밋·배포 또는 인증된 브라우저 E2E는 수행하지 않았다. 디자인·스키마·환경변수·의존성도 변경하지 않았다.
- 처리하는 오류는 `router.push`/`router.refresh` 호출의 동기 오류다. 이후 비동기 네트워크/렌더링 실패나 목적지 도착을 모두 감시하는 새 오류 경계는 추가하지 않았다.
- 알림은 서버 변경 결과를 뜻하며 목적지/새 데이터의 완전한 렌더링을 증명하지 않는다. 실패 안내 시 서버 상태를 되돌리는 쓰기나 자동 재시도는 하지 않는다. 안내 확인 후 수동 요청은 기존처럼 가능하다.
