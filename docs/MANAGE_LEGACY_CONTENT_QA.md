# Works·Crew 예전 형식·미지원 본문 점검

## 재현한 문제

- Works의 보존 블록 제목이 라벨 객체의 상속 속성까지 조회했다. 종류가 `constructor`·`toString` 등이면 종류명 대신 함수 문자열이, `__proto__`면 객체 문자열이 표시됐다.
- Crew의 미지원 섹션은 내부 `items`를 날짜·제목 객체로 단정했다. 알 수 없는 본문에 null이나 객체형 제목이 있으면 편집 화면이 깨질 수 있었다. 지원되는 옛 수상·활동의 문자열 행도 실제 내용이 보이지 않았다.
- 옛 수상·활동을 새 형식으로 전환하면 날짜·제목 외 설명과 추가 정보, 제목 없이 날짜만 있던 행이 빠질 수 있었다. 전환 전 확인창은 이러한 손실을 알리지 않았다.
- 최초 편집기 회귀 테스트 14개 중 **13개가 수정 전 실패**했고, 전환 취소의 기존 동작 1개는 통과했다. 실제 운영 데이터에서 손실이 발생했다고 확인한 것은 아니다.

## 반영 내용

- Works의 라벨은 객체 자체 속성만 조회한다. 등록된 자유서식 라벨은 유지하고, 모르는 종류는 원래 종류명을 문자열로 표시한다. 보존 블록의 삭제 금지·순서 변경·서버 원본 참조 규칙은 바꾸지 않았다.
- Crew에서 알 수 없는 섹션의 본문은 임의로 해석하지 않는다. 종류와 보존 안내, `/admin`에서 세부 내용을 확인하라는 안내를 표시한다. 폼 JSON에는 기존처럼 키·종류·보존 표지만 보내며 실제 내용은 서버 원본을 사용한다.
- 전환을 지원하는 옛 수상·활동만 별도의 안전한 읽기 전용 표시로 다룬다. 문자열과 날짜·제목·설명을 표시하고, 잘못된 자료형을 객체 문자열로 바꾸거나 React 자식으로 넣지 않는다.
- 공통 `legacyMigrationIssue`를 전환 버튼과 `migrateLegacy`가 함께 사용한다. 설명이 있거나 새 형식에서 보존할 수 없는 추가 필드, 제목 없이 날짜만 있는 행, 해석할 수 없는 목록이 있으면 자동 전환하지 않는다. 원본 유지와 `/admin` 확인을 안내하며, 다른 필드의 저장은 계속 가능하다.
- 기존 전환 대상은 `awardsSection`·`activitiesSection` 두 종류다. 안전한 날짜·제목 행과 옛 문자열 행은 확인 후 새 수상·활동으로 옮길 수 있다. 새 섹션을 만들거나 기존 같은 섹션 뒤에 추가하며 반대편 목록은 유지한다. 확인 취소 시 dirty 상태와 제출 JSON은 변하지 않는다.
- 빈 선택 값·빈 설명·빈 목록에는 새 제한을 강제하지 않는다. 전환 후 빈 항목 제거와 공백 정리 등 기존 저장 규칙은 유지한다. 전환이 허용된다는 것이 공백·옛 객체 키까지 바이트 단위로 그대로 복제한다는 의미는 아니다.
- 원본을 추측해서 고치거나 전환을 자동 실행하지 않는다. 변경은 기존처럼 사용자가 실제 저장해야 반영된다. 스키마·공개 페이지 디자인·권한·revision·캐시 정책은 변경하지 않았다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽었다. 저장 액션에 새 권한 예외를 추가하지 않았다.

## 검증

새 테스트 **46개**를 추가했다.

- 편집기 DOM **15개**: 상속 속성 이름의 Works 라벨·보존/삭제 금지, Crew 미지원 내용의 안전한 표시, 옛 문자열 표시·전환, 전환 불가 안내·원본 참조 유지, 확인 취소, Works 보존 블록 재정렬·재편집·재저장.
- 전환 모델 **29개**: 두 옛 종류의 전환·기존 섹션 병합·손실 가능성 차단·원본 불변성·미지원 전환 거부·읽기 전용 표시 자료형.
- 실제 Crew 조회 페이지→폼→액션→모의 저장소→새 revision 재조회 **2개**: 이름을 두 번 저장해도 미지원/전환 불가 원본 전체 보존, 명시적 전환 뒤 새 형식과 항목 키가 반복 저장에서도 유지됨.

전체 **3,046개 / 90개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 스모크도 **37/37 통과**했다.

공개 API의 Crew **3건**, Works **8건**을 읽기 전용으로 집계했다. 현재 본문 읽기 차단은 **0건**, 옛/미지원 Crew 섹션과 Works 보존 블록도 **0개**였다. 현재 공개 데이터에 전환이나 복구가 필요하다고 판단한 것은 아니다. 원문·문서 ID·인증 정보는 출력하지 않았고 CMS 쓰기를 하지 않았다.

## 범위와 한계

- 표시와 공통 클라이언트 전환 모델의 보호다. 서버에 제출된 임의의 전체 본문 변경을 모두 금지하는 새 정책이 아니다. Crew의 명시적 섹션 삭제와 직접 승인된 다른 편집은 기존 계약을 따른다.
- 모르는 추가 필드가 실제로는 불필요한 메타데이터여도 자동 전환을 보수적으로 막는다. 필요하면 원본을 확인한 뒤 별도 변환 규칙을 정해야 한다. 원본을 삭제하거나 정보를 추측해 새 필드로 옮기지 않는다.
- 알려진 일반 편집 블록의 모든 확장 필드까지 무손실 보존한다고 보장하지 않는다. 일반 편집 형식의 필드 재구성·빈 항목 정리는 기존 정책이다.
- 정상 공개 데이터에는 해당 예전/보존 형식이 없었다. 테스트의 예전 본문·저장소·인증·업로드·router refresh는 모의 구현이며 운영 문서를 실제 저장·전환하거나 인증된 운영 브라우저 E2E를 수행하지 않았다.
- 커밋·배포·환경변수·의존성 변경은 하지 않았다. 새 안내의 실제 시각·스크린리더 검증은 별도다.
