# 공개 콘텐츠 실패·빈 상태 점검

## 반영 내용

### CMS 이미지

- 기존 최적화 경로를 유지하면서, 이미지 error 이벤트가 발생하면 외부 요청이 필요 없는 내장 SVG로 대체한다.
- 허용하지 않는 원격 주소·잘못된 문자열은 Next Image 렌더링 예외로 이어지기 전에 대체한다. Next 원격 허용 설정과 CSP를 넓히지 않았다. 로컬 사진·Sanity CDN·기존 image data URL/blob 지원을 유지한다.
- fill 사진은 기존 부모 프레임을 유지한다. 크기가 있는 사진은 선언된 width/height 또는 정적 import 메타데이터 비율에 맞는 SVG를 사용한다. `height: auto`인 이미지가 오류 후 정사각형으로 커지지 않도록 했다.
- 정상 사진의 crop·class·style·CDN 로더·blur·지연 로딩은 그대로다. 오류 상태에서는 blur를 제거한다.
- 원본 error 콜백은 한 번 전달하고, 대체 SVG 로드를 원본 onLoad 성공으로 전달하지 않는다. alt가 빈 장식 이미지는 실패해도 오류 문구를 보조기기에 추가하지 않는다.
- 원본 src가 바뀌면 사진의 오류 상태만 초기화한다. 부모 캐러셀·모달·입력 상태를 초기화하지 않는다. 자동 무한 재시도는 추가하지 않았다.

### 빈 Crew와 로딩 안내

- Crew 목록이 비었거나 모든 slug가 공개 경로로 사용할 수 없는 경우 `등록된 크루가 없습니다.`를 표시한다. 실제 CMS 문서의 수정·삭제는 하지 않는다.
- Works·Crew·Class 로딩 화면에 화면낭독기용 상태 문구를 추가하고, 도형들은 aria-hidden으로 구분했다. 상태 안내를 aria-busy 영역 안에 넣어 읽기가 억제되지 않게 했다.
- 로딩 화면에는 실제 페이지의 `page-title`이나 h1을 만들지 않는다. 기존 본문 포커스와 상세 스모크가 로딩 화면을 완성된 내용으로 오인하지 않게 한다.

## 검증

- 전체 자동 테스트 **1,081개 / 48개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과.
- 실제 Next Image를 사용하는 기존 SSR 최적화 테스트 5개 유지. 새 클라이언트 테스트에서 error 처리, 장식 alt, 원본 콜백, blur 제거, 사진 교체, 부모 상태, 정적 import 크기 보존을 확인했다.
- 허용/거부 src와 SVG 숫자 치수·예약 비율의 단위 테스트 추가. 사용자 URL·alt·캡션은 SVG 코드에 넣지 않는다.
- 로딩 화면 3곳의 상태 문구·장식 구분과 Crew 빈 목록/잘못된 slug만 있는 목록을 테스트했다.
- 로컬 스모크 **35/35 통과**. 기존 `n@di – 사랑의 형태` 상세 404 수정도 유지됐다.

## 실제 브라우저 예시

운영 문서를 만들지 않고 임시 로컬 페이지에서 다음을 확인했다.

1. 존재하지 않는 로컬 사진의 실제 404 → 내장 대체 이미지 표시. 지원하지 않는 외부 호스트도 페이지 오류 없이 대체.
2. 정상 사진으로 src 교체 → 실제 이미지 로드 성공, 기존 입력값 `작성 내용 유지` 보존. 모바일 fill 프레임도 전후 319×238px로 동일.
3. 600×300 예약 비율의 반응형 실패 이미지: 넓은 화면 720×360px, 375px 화면에서 321×160.5px로 2:1 비율 유지.
4. 빈 Crew 상태에서 제목과 안내 문구 표시.

검증 중 의도한 누락 사진 2개의 404 서버 로그는 예상된 결과다. 지원하지 않는 외부 주소 때문에 React/Next 렌더링 예외가 발생하지는 않았다.

임시 `qa-media-check` 소스는 제거했다. 그 빌드는 `/private/tmp/whitelight-media-qa-wnB1x4/qa-build`로 분리한 뒤 새 최종 빌드를 만들었으며, 최종 매니페스트에 해당 경로가 없고 실제 요청도 404임을 확인했다. **이 백업은 검증용 페이지가 들어 있는 산출물이며 배포용이 아니다.**

최종 빌드의 실제 Crew에서도 프로필 링크 3개와 정상 화면을 확인했다. 이 확인 시 대체 이미지로 바뀐 항목과 콘솔 오류/경고는 없었다.

## 한계 및 범위

- 동영상 서비스 내부의 삭제·비공개 상태나 서버가 응답을 계속 보류하는 경우까지 자동 판별하는 기능은 아니다.
- 오디오의 기존 취소·재시도·error 처리는 유지했으며, 새 재생 정책이나 강제 타임아웃은 추가하지 않았다.
- 실제 VoiceOver/NVDA 음성 출력과 물리 모바일 검증을 대신하지 않는다.
- 정상 콘텐츠의 디자인, 콘텐츠 데이터, 환경변수, 의존성, 커밋·배포는 변경하지 않았다. 사진을 새로 제작하거나 CMS에 업로드하지 않았다.
