# 이력 복원 버튼의 응답·화면 이동 점검

## 확인한 문제

- 버튼이 액션 결과를 직접 읽어 `ok: "true"` 같은 비정상 응답도 성공으로 처리했다. 오류 문구의 자료형이 잘못되면 안내가 비거나 숫자가 표시될 수 있었다.
- 화면 이동 전에 성공 알림을 브라우저 저장소에 예약했다. 이동 호출이 실패해도 이번 작업의 성공 알림이 뒤늦게 다른 화면에서 표시될 수 있었다.
- `startTransition` 콜백 안의 `router.push()` 동기 오류가 바깥 비동기 작업의 catch에 잡히지 않는 것을 DOM 테스트로 재현했다. 복원 완료와 이동 실패를 구분하는 안내도 없었다.
- 모의 액션·라우터로 재현했으며 실제 운영에서 복원 데이터가 손상됐다는 확인은 아니다.

## 반영 내용

- 기존 공통 `callManageAction`으로 액션 응답을 검사한다. 자체 불리언 `ok`·유효한 오류 문구/필드 오류만 사용한다. 응답 불명과 전송 예외는 복원 결과 재확인 안내로 바꾸며 자동 복원 재요청을 하지 않는다.
- 서버가 구분한 결과 불명·복원 후 캐시 갱신 실패·버전 충돌 안내는 그대로 표시한다.
- 유효한 성공 응답을 받은 뒤 이동을 전환 안에서 호출한다. 그 동기 오류는 같은 콜백 안에서 처리해 “복원은 완료됐지만 화면을 이동하지 못했어요”로 안내한다. 서버에 복원을 다시 보내지 않는다.
- 이번 작업의 성공 알림은 이동 호출이 동기 오류 없이 반환된 뒤에만 예약한다. 이동 완료를 기다리는 새 Promise나 임의 타이머는 만들지 않았다.
- 공통 잠금·동일 프레임 중복 요청 차단·늦은 응답의 현재 주소 확인은 유지한다. Next 제어 신호는 공통 함수와 이동 오류 처리에서 `unstable_rethrow`로 전달하며 일반 통신 안내로 바꾸지 않는다.
- 디자인·복원 확인창·서버 저장 로직·스키마·환경변수·의존성은 변경하지 않았다.

설치된 Next.js의 `use-client.md`, `04-functions/use-router.md`, `04-functions/unstable_rethrow.md`를 읽었다. `router.push`를 이동 완료 Promise로 취급하지 않는다.

## 검증

DOM 테스트 **17개**를 추가하고 기존 성공 테스트에 이동 호출→알림 예약 순서 검사를 보강했다.

- 비정상 응답 11종의 결과 확인 안내·알림/이동/재요청 없음·잠금 해제.
- 서버의 결과 불명/확인된 변경 후 갱신 실패 안내 2종 보존.
- 이동 호출 동기 오류 1종의 복원 완료 안내·알림 예약 없음·잠금 해제·원문 미노출.
- Suspense로 이동 렌더링을 지연시키는 1종에서 요청이 끝나도 잠금 유지.
- 주소 변경 뒤 성공/실패 응답 2종의 알림·이동·오류 표시 생략.
- 보완 전에는 기존 성공 테스트의 강화된 조건을 포함해 11개가 실패했고 보완 후 통과했다. 기존 중복 클릭·취소·수동 재시도와 공통 액션/변경 잠금 테스트도 회귀 확인했다.
- 전체 **4,547개 / 106개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했으며 임시 서버는 종료했다.

## 범위와 한계

- 액션·라우터·알림은 모의 구현이고 React DOM/잠금 훅은 실제 코드를 사용했다. 운영 복원·업로드·커밋·배포 또는 인증된 브라우저 E2E는 수행하지 않았다.
- 처리하는 이동 오류는 `router.push()` 호출 시 동기 오류다. 이후 비동기 네트워크/렌더링 실패를 모두 탐지하거나 목적지 도착을 보장하는 새 오류 경계·경로 감시 기능은 추가하지 않았다.
- 이동 호출 이후의 성공 알림은 복원 작업의 성공을 뜻하며 목적지의 완전한 로드를 증명하지 않는다. 알림 저장소를 사용할 수 없으면 기존 `flashToast`가 알림만 생략한다.
- 자동 재시도는 하지 않지만 안내 확인 후 수동 요청은 기존처럼 가능하다. 여러 브라우저의 모든 요청을 멱등 처리하는 새 프로토콜은 아니며 서버의 현재 버전 조건은 유지된다.
