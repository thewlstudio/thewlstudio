# 관리 허브·변경 이력 읽기 점검

## 확인한 문제

- 허브의 현황·최근 수정 응답은 타입 선언만 믿고 사용했다. 잘못된 제목·수정 시각은 렌더링 오류를 내고, 객체 기본 속성 이름과 같은 문서 종류는 종류별 메타데이터 조회에 잘못 걸릴 수 있었다.
- 조회 예외는 최근 수정 `[]`·현황 `null`로 바꾸면서 실패 안내를 하지 않았다. 운영자가 실제 빈 기록과 조회 실패를 구분하기 어려웠다. 잘못된 건수와 전체보다 많은 비공개 건수도 표시할 수 있었다.
- 이력은 실제 현재 문서가 있어도 보관된 저장 기록이 비어 있으면 404로 처리했다. 보관 범위 밖의 선택 시점도 별도 안내가 없었다.
- 이력 NDJSON 응답을 `String()`으로 강제 변환해, 배열 응답 `[]`가 빈 정상 기록처럼 처리될 수 있었다. 저장 시점/ID 중복도 그대로 표시해 선택 링크와 행 식별을 모호하게 할 수 있었다.
- 스냅샷의 `documents`가 배열인지 확인하지 않고 첫 값을 읽었다. 배열처럼 생긴 객체나 여러 결과 중 첫 문서가 올바른 메타데이터를 가지면 복원 후보로 받아들일 수 있었다. 공백뿐인 문서 revision도 유효한 버전처럼 취급했다.

## 허브 반영 내용

- 현황과 최근 수정을 각각 `unknown`으로 조회하고 독립적으로 판별한다. 두 조회는 병렬로 실행하되 어느 한쪽 실패로 관리 허브 전체를 막지 않는다.
- 현황의 필요한 7개 값은 음수가 아닌 안전한 정수여야 하고, 비공개 건수는 전체보다 클 수 없다. 잘못된 응답을 0건으로 꾸미지 않고 해당 배지를 생략하며 `role="status"` 안내를 표시한다.
- 최근 수정의 목록·행·공개 문서 ID·중복 ID·알려진 종류·유효한 표시 시각·제목 자료형을 검사한다. 고정 설정은 실제 고정 ID까지 맞아야 해당 설정 화면으로 연결한다. 메타데이터 조회는 객체의 자체 속성만 인정한다.
- 최근 수정 한 행이 잘못됐다고 그 행만 조용히 빼지 않는다. 보조 목록을 생략하고 읽기 실패를 안내하되 현황과 다섯 관리 메뉴는 유지한다. 실제 빈 배열은 실패로 표시하지 않는다.
- 정상 제목 누락/빈 값의 기존 종류별 라벨, 관리 링크·현황 문구는 유지한다. 원본의 불필요한 추가 필드를 반환하지 않는다. 오류 객체나 잘못된 원문을 실패 안내에 출력하지 않는다.

## 이력 반영 내용

- 거래 이력은 실제 문자열 NDJSON만 파싱한다. 유효한 빈 문자열/공백은 빈 기록이며 다른 자료형을 문자열로 강제 변환하지 않는다. 기존 JSON·시각 검사를 유지하고 공백 ID, 중복 ID·정확히 같은 시각 문자열을 거부한다.
- 현재 선택 경로가 `?at=<시각>`이므로 같은 시각이 두 번 있으면 어떤 행을 뜻하는지 모호하다. 자동 병합하거나 첫 기록으로 복원하지 않고 기존 조회 실패 안내로 처리하는 보수적 정책이다. 다른 revision 선택 방식으로 바꾼 것은 아니다.
- 특정 문서 하나의 스냅샷은 `documents` 배열이 0~1개 결과인지 확인한다. 배열처럼 생긴 객체·여러 후보·문서가 아닌 행은 형식 오류다. 빈 배열/빈 후보는 복원 가능한 문서가 없음을 뜻한다.
- 문서 후보는 실제 객체와 일치하는 ID·종류·비어 있지 않은 revision을 요구한다. 이 검사는 화면과 복원 액션이 공유하므로, 잘못된 스냅샷에서는 실제 패치·캐시 갱신을 시작하지 않는다.
- 현재 문서가 있지만 보관된 기록이 없으면 404 대신 빈 기록 안내와 수정 화면 복귀 경로를 제공한다. 선택한 기록이 현재 표시 범위에 없으면 아래 목록에서 다시 고르도록 안내한다.
- 기존 인증·다른 ID/종류의 404·스냅샷 개별 조회 실패·복원 직전 revision 조건부 패치·휴지통/순서 유지·공개 캐시 갱신 규칙은 유지했다. 원본 본문을 새 스키마로 자동 정리하거나 변경하지 않는다.

응답 구조는 [Sanity History API](https://www.sanity.io/docs/http-reference/history)와 [Doc API](https://www.sanity.io/docs/http-reference/doc)를 확인했다. 거래 목록은 NDJSON이고 시점 조회는 문서 배열을 반환하는 계약을 기준으로 검사한다. 문서 본문의 `_updatedAt`을 거래 시각이나 revision ID와 동일하다고 가정하지 않았다. 설치된 Next.js 16.4.3의 `use-server.md`도 읽었다.

## 검증

새 테스트 **105개**를 추가했다.

- 허브 판별 **63개**: 현황·숨김 건수·최근 목록/행·식별자·종류·시각·제목·고정 설정·중복·원본 불변성·추가 필드 미반환.
- 실제 허브 SSR **19개**: 정상 표시, API 예외/비정상 응답의 독립적인 실패 안내와 메뉴 유지, 정상 빈 목록, 고정 문서 라벨·잘못된 고정 ID.
- 이력 도우미 **16개**: NDJSON/스냅샷 컨테이너·다중 결과·실제 빈 기록·중복 ID/시각·문서 메타데이터.
- 실제 이력 SSR **3개**: 빈 기록 안내, 선택 시점 미발견 안내, 중복 시점의 후보 미표시.
- 실제 복원 액션 **4개**: 잘못된 스냅샷 응답·공백 revision에 패치/캐시 갱신 미실행, 원문 오류 미노출. 외부 저장소는 모의 객체다.

전체 **2,905개 / 77개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 스모크도 **35/35 통과**했다.

현재 공개 허브의 같은 쿼리를 읽기 전용으로 실행하고 실제 판별 함수를 적용했다. 현황은 **강사 7명·Crew 3명·Works 8개·연습실 4개·로비 1개**, 강사/Crew 비공개 각 0명으로 정상이며 최근 수정 **6건**도 통과했다. 제목·문서 ID·인증 정보는 출력하지 않았고 CMS 쓰기는 하지 않았다.

## 범위와 한계

- 운영 이력 API는 인증이 필요한 별도 영역이다. 이번 실행에서 해당 API에 접근하거나 실제 복원을 수행하지 않았다. 이력은 모의 응답·실제 페이지와 액션 호출로 검증했으며 인증된 운영 브라우저 E2E를 완료했다는 뜻이 아니다.
- 중복된 시각이 있다면 실제 거래가 유효해도 현재 시각 기반 UI에서는 전체 이력을 열지 않는다. 임의의 거래를 고르지 않기 위한 제한이며, 필요한 경우 기존 `/admin`이나 revision 기반 별도 개선으로 확인해야 한다.
- 스냅샷 메타데이터와 응답 구조를 검사하는 것이지 과거 본문 전체가 현재 편집 스키마에 맞음을 보장하지 않는다. 다른 시점으로 되돌리는 기존 기능의 의미를 바꾸거나 이력 내용을 자동 수정하지 않는다.
- 허브는 요약 정보다. 보조 조회가 실패해도 관리 메뉴는 사용할 수 있으며, 실제 편집/목록은 각각의 읽기 보호와 저장 검증을 따른다.
- 정상 공개 디자인·운영 데이터·스키마·환경변수·의존성·커밋·배포는 변경하지 않았다. 새 안내의 시각·스크린리더 실기 검증은 별도다.
