# 상세 페이지 이동·제목 포커스 연결 점검

## 확인한 문제와 수정

- Works 상세의 `data-page-path`는 `initialWork.slug`에서 만들고 있었지만 실제 상세 GROQ 조회에는 그 필드가 없다. 같은 작품 화면 DOM을 재사용해 다른 작품으로 이동하면, 새 경로임을 식별하지 못해 자동 포커스가 끝나지 않을 수 있었다.
- 서버 페이지가 이미 검증·계산한 `path`를 Works 상세 클라이언트에 직접 전달한다. Crew와 같은 방식이며 CMS 응답에 slug를 억지로 채워 넣거나 조회/저장 규약을 바꾸지 않았다. 단독 렌더링 호환용 기존 slug 대체는 유지하지만 실제 서버 진입점은 명시적인 경로를 전달한다.
- URL의 안전한 인코딩 표기 차이 때문에 새 제목을 다른 페이지로 오인하지 않도록 `pagePathMatches`를 사용한다. 경로를 `/`로 나눈 다음 각 조각을 **한 번만** 해석해 비교하므로 `%2F`를 실제 경로 구분자로 합치거나 리터럴 퍼센트를 재귀 해석하지 않는다. 대소문자가 다른 실제 이름은 같다고 보지 않는다. 이 함수는 포커스 비교용이며 인증/리다이렉트 검증기를 대체하지 않는다.
- 자동 포커스의 관찰 대상에 `hidden`/`aria-hidden` 변경을 추가했다. 잠긴·숨겨진 제목이 실제 표시될 때 완료하며, 로딩 중 이전 페이지의 경로 표식은 기다린다.
- 본문 바로가기도 현재 URL과 다른 이전 제목, 이미 있지만 잠긴/숨겨진 제목을 즉시 포커스하지 않고 준비를 기다린다. 지연된 제목의 경로 표식 변경도 관찰한다. 일반 Next 링크의 해시/탐색 기록 동작을 별도로 구현하거나 패치하지 않았다.

## 유지한 사용성

- 최초 진입, 같은 pathname의 검색 조건 변경, 뒤로/앞으로 복원에서는 새 포커스를 강제하지 않는다.
- 새 화면에서 사용자가 선택한 입력·링크·대화상자의 포커스를 빼앗지 않는다. 관리 화면·Sanity Studio도 기존 제외 정책을 유지한다.
- 제목이나 본문 섹션이 화면 밖/고정 헤더 뒤에 있을 때만 기존 드러내기 정책을 사용한다. 제목 문구·레이아웃·모션·공개 캐시는 바꾸지 않았다.
- 관찰자는 완료·경로 전환·컴포넌트 해제 때 정리한다. 새 전역 타이머, 라우터 패치나 가짜 탐색 기록을 넣지 않았다.

## 기준과 검증

- 설치된 Next.js의 `use-pathname.md` 전체와 useRouter의 스크롤/탐색 설명을 확인했다. 실제 경로는 클라이언트 훅, 제목의 올바른 대상 경로는 서버가 검증한 값을 사용한다.
- 새 DOM 회귀 테스트 **24개**와 기존 Works 인코딩 7건의 서버→클라이언트 path 전달 검사를 보강했다. 최초 재현 단계에서 경로/숨김 해제 문제와 새 연결 검사를 포함해 19개 실패를 확인한 뒤 수정했다.
- 실제 Works/Crew 상세와 포커스 제어기를 연결해 DOM 재사용, slug 없는 조회 결과, 잘못된 source slug보다 서버 path 우선, 한글/퍼센트, 이전 본문 대기, 사용자의 입력 포커스 보존을 확인한다. Motion만 단순 DOM으로 대체한다.
- 자동 포커스/본문 바로가기의 숨김 해제, 인코딩 별칭, 다른 경로를 합치지 않는 비교도 확인했다. 기존 로딩·inert·해시·탐색 기록·해제 시 정리 검사도 통과했다.
- 전체 **5,072개 / 120개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 스모크 **41/41 통과**, 공개 상세 **11개**의 유일한 제목 대상·`tabindex=-1`·실제 경로 표식 일치도 확인했다.
- 실제 로컬 브라우저에서 Works 목록의 인코딩된 `@` 주소 링크를 키보드 Enter로 열었다. 상세 진입 후 활성 요소가 `page-title` 그룹이며 `data-page-path`가 실제 주소와 일치함을 DOM/접근성 트리에서 확인했다. 음성 낭독 검증을 뜻하지 않는다. 임시 검증 탭과 서버는 정리했다.

## 범위와 한계

- DOM 포커스와 실제 페이지 연결을 검증한 것이며 VoiceOver/NVDA 음성 낭독을 직접 듣고 평가한 결과는 아니다.
- 준비 상태는 DOM 삽입·경로 표식·inert/hidden/aria-hidden 속성을 기준으로 한다. 모든 CSS class/style 변경을 관찰하는 전역 감시기를 추가하지 않았다.
- 프레임워크의 네이티브 스크롤/해시/탐색 복원 자체를 재구현하지 않았다. 관찰 도중 다른 입력을 선택하면 지연된 자동 이동을 포기한다.
- 운영 데이터·업로드·환경변수·의존성·스키마·디자인·커밋·배포는 변경하지 않았다.
