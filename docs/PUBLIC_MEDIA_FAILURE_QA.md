# 공개 이미지·영상·오디오 실패 상태 점검

## 확인한 문제와 수정

- 오디오 파일 오류가 발생해도 이전 재생 길이와 진행률이 상태에 남았다. 그 결과 오류 안내와 함께 여전히 조작 가능한 진행 바가 표시될 수 있었다.
- 파일 오류 때 길이·진행률을 초기화하고 탐색을 비활성화한다. 오류가 남은 파일의 늦은 메타데이터/진행 이벤트로 탐색을 되살리지 않는다.
- 길이가 유효했다가 알 수 없는 값으로 바뀌는 경우도 이전 진행률을 제거한다. 길이 변경 이벤트보다 진행 이벤트가 먼저 와도 같은 기준을 사용한다.
- 탐색 처리 자체도 현재 파일 오류를 확인한다. 오류 안내가 화면에 반영되기 전에 도착한 조작으로 실패한 파일의 재생 위치를 바꾸지 않는다.
- 재시도는 기존처럼 파일을 다시 읽으며 새 길이를 확인한 뒤 탐색을 허용한다. 파일 오류 없이 재생 권한만 거절된 경우에는 유효한 길이와 위치를 지우지 않는다. 정상 재생·일시정지·곡 전환·탭 제목/파비콘 정리는 기존 동작을 유지한다.

## 이미지·영상 확인

- 기존 `CmsImage`는 실패 시 외부 요청 없는 대체 표시, 예약 크기/비율 유지, 장식 사진의 빈 대체 텍스트, source 교체 시 사진만 복구하는 처리를 갖추고 있다. 실제 Next Image 연결 검사 13개가 통과했으며 이미지 구현은 변경하지 않았다.
- 작품 영상의 URL 검증·유효한 YouTube 주소만 임베드하는 검사와 사진 없는 커버의 영상 링크 이름도 확인했다. 외부 영상의 삭제·비공개 상태를 임의로 추측하거나 새 디자인/버튼을 추가하지 않았다.

## 기준과 검증

- 설치된 Next.js 16.4.3의 Image 문서에서 `onLoad`·`onError` 설명을 확인했다.
- 미디어 오류 객체의 의미는 [MDN error 문서](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/error), 길이 정보가 없을 때의 NaN·길이가 정해지지 않았을 때의 Infinity는 [MDN duration 문서](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/duration)를 확인했다. 이 값들을 바탕으로 진행 바 상태를 어떻게 안내할지는 이 프로젝트의 처리 정책이다.
- 회귀 검사 9개를 추가했다. 모의 미디어 오류와 길이 변경으로 수정 전 5개 실패를 재현했다. jsdom에 없는 오류 getter는 테스트 재생기 인스턴스에만 제공하며, 실제 오디오 파일이나 운영 문서를 변경하지 않는다.
- 파일 실패 후 탐색 중지/진행률 제거, 늦은 이벤트 무시, 새 길이를 받은 재시도, 알 수 없는 길이, 화면 반영 전 입력과 재생 권한 거절을 각각 검사했다.
- 전체 **5,159개 / 121개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 기존 재생 경쟁 상태·재생 거절·여러 곡 전환·화면 해제·탭 제목/파비콘·동작 줄이기 검증도 통과했다. 최종 빌드의 읽기 전용 로컬 스모크 **42/42 통과** 후 임시 서버를 종료했다.

## 범위와 한계

- 실제 React 컴포넌트에 모의 브라우저 미디어 이벤트/재생 Promise를 연결한 검사다. 운영 파일을 삭제하거나 실제 외부 서버 장애·모든 브라우저 코덱 재생을 유발해 평가한 결과는 아니다.
- 외부 영상의 실제 재생 가능 여부와 삭제/비공개 여부를 검증 완료로 표현하지 않는다.
- 디자인·공개 문구·파일 주소·콘텐츠·업로드·환경변수·의존성·스키마·커밋·배포는 변경하지 않았다.
