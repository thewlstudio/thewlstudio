# 서버 저장 완료·캐시 실패 상태와 폼 보호 연결

## 확인한 경계

- 서버는 저장 응답을 검증한 뒤 캐시를 갱신하고 있었다. 갱신 실패는 고정 문구로 안내했지만, `ok: false` 응답만으로는 폼이 일반 저장 실패와 확인된 저장 후 갱신 실패를 구분할 수 없었다.
- 브라우저 refresh 동기 오류에만 적용한 기준값 보호를 서버 캐시 실패까지 연결해야 했다. 문구를 비교하거나 원본 ID·문서 내용을 전달해 추측하는 방식은 사용하지 않는다.
- 결과 불명은 실제 미반영을 뜻하지 않으며, 이를 확인된 저장으로 잘못 승격해서도 안 된다.

## 반영 내용

- 저장 응답 검증 뒤의 갱신 오류를 전용 `ManagedRefreshError`로 구분한다. 기존 결과 불명 오류와 같은 상위 종류를 유지해 기존 안내 경로는 깨뜨리지 않는다.
- 폼용 `managedSaveFailure`는 전용 오류에만 `committed: true`를 붙인다. 문구가 같아도 일반 Error/결과 불명/409에는 붙이지 않는다. 저장 요청 자체의 예외는 기존 결과 불명 경로로 처리한다.
- 강사·Crew·Works·공간·연락처·Studio 안내의 수정 저장에 연결했다. 네 일반 생성 폼은 검증된 새 ID를 받은 뒤 캐시 단계가 실패한 경우에만 표시를 붙인다. 단일 설정 문서의 최초 생성도 검증된 생성 뒤 갱신 오류를 같은 방식으로 전달한다.
- 전달하는 추가 정보는 저장 확인 여부 한 개뿐이다. 문서 ID·원문·버전·에셋·오류 객체를 새로 반환하지 않는다. 인증·입력 검증·버전 조건·응답 확인은 유지한다.
- 공통 클라이언트는 실패 응답의 자체 속성 `committed: true`만 허용한다. false·문자열·자체 undefined·상속 속성·성공 응답의 표시는 비정상 응답으로 처리한다. 표시가 없으면 문구에서 저장 사실을 추정하지 않는다.
- 폼은 표시가 있는 실패에서 서버 안내를 유지하며, 이전 단계의 revision별 기준값 보호를 활성화한다. 같은 화면의 재저장 전송과 변경 버리기를 보류하고 입력을 유지한다. 새 revision을 받으면 보호와 이전 갱신 실패 안내를 해제한다.
- 생성 폼도 다시 생성하지 않으며 선택 파일을 보존한다. 새 ID를 응답에서 추측해 이동하거나, 이미 저장된 문서를 롤백/삭제하지 않는다.
- 정상 성공·일반 입력 오류·인증 만료·충돌·요청 결과 불명 처리는 유지한다. 디자인·스키마·환경변수·의존성은 변경하지 않았다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽고 서버 함수 반환값을 필요한 최소 정보로 제한했다.

## 검증

새 테스트 **38개**를 추가했다.

- 실제 서버 액션 12개: 여섯 수정 저장과 여섯 최초 생성 경로의 확인된 저장 뒤 캐시 실패 표시. 생성 경로는 네 일반 문서와 두 고정 설정 문서다.
- 오류 분류 6개: 전용 오류·같은 문구의 다른 오류 2종·문구 변경·409·저장 요청 자체 예외를 구분한다.
- 공통 응답 검사 6개: 정상 표시 1종과 비정상 표시 5종을 확인한다.
- 실제 폼 DOM 14개: 여섯 폼의 보호 6종·새 revision 회복 6종, 문구만 같은 응답에서 의미를 추측하지 않는 1종, 생성 폼의 파일/입력 보존과 재생성 차단 1종.
- 기존 요청 예외 검사에도 `committed` 미포함을 확인했다. 기존 생성/수정 응답·충돌·늦은 응답·공유 잠금·정상 버리기 테스트도 회귀 확인했다.
- 전체 **4,648개 / 108개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했으며 임시 서버는 종료했다.

## 범위와 한계

- CMS·인증·캐시·라우터는 모의 구현이고 React DOM/폼 보호는 실제 코드다. 서버 액션의 반환 계약과 실제 폼의 소비를 각각 검사한 것이며, 인증된 브라우저→실제 CMS 종단 테스트는 아니다.
- 운영 저장·생성·업로드·커밋·배포는 수행하지 않았다.
- `committed`는 서버가 저장 응답을 검증했다는 뜻이다. 공개 캐시가 갱신됐거나 최신 화면 데이터가 도착했다는 뜻은 아니다. 클라이언트 요청 인자를 신뢰해 이 값을 정하지 않는다.
- 표시가 없는 예전 서버 응답이나 비정상 표시를 안내 문구로 보완 추측하지 않는다. 서버·클라이언트 변경을 함께 배포해야 전체 연결이 적용된다.
- 새 revision이나 새 페이지 진입 전까지 보수적으로 입력 보호를 유지한다. 같은 revision의 무변경 저장이나 브라우저의 모든 비동기 갱신 완료를 독립적으로 증명하는 readback 프로토콜은 아니다.
- 다른 브라우저/새로고침을 포함한 영구 멱등성이나 일반 네트워크 결과 불명의 자동 복구는 추가하지 않았다. 입력 보관과 현재 내용 확인이 필요하다.
