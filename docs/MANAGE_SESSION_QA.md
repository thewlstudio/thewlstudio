# 관리자 로그인·세션 경계 점검

## 반영 내용

`src/lib/manage-auth.ts`의 검증만 보완했다. 로그인 방식·비밀번호 값·서명 알고리즘·정상 쿠키 형식·12시간 유효기간·발급 옵션은 유지한다.

- 만료 판단을 `현재 시각 > 만료 시각`에서 **현재 시각 ≥ 만료 시각**으로 정정했다. 만료 시각과 정확히 같은 때에도 더 이상 인증하지 않는다.
- 발급한 그대로의 `양의 정수 만료 시각.64자리 소문자 16진수 서명`만 받는다. 뒤에 붙은 구간·공백·숫자의 다른 표기·무한대·안전한 정수가 아닌 값은 거부한다.
- `MANAGE_PASSWORD` 또는 `MANAGE_SECRET`이 비어 있는 상태에서는 기존 쿠키도 인증하지 않는다. 설정을 다시 채우면 아직 만료되지 않은 기존 쿠키가 다시 유효할 수 있으므로, 이는 영구 세션 폐기 기능은 아니다.
- `isAuthenticated`와 `getSessionExpiry`가 같은 검증을 사용한다. 만료 시각 반환을 위해 쿠키를 두 번 읽지 않는다.

변경 전 새 검증 중 12개가 실패하는 것을 재현한 뒤 통과를 확인했다. 이 수는 별개의 취약점 12개를 발견했다는 뜻이 아니며, 중복 쿠키 조회 확인도 포함한다.

형식 변형 사례는 **정상 서명을 이미 가진 테스트 쿠키**로 검사했다. 서명 없이 로그인할 수 있거나 HMAC을 위조할 수 있는 인증 우회를 발견했다는 뜻은 아니다. 기존 방식으로 발급한 정상 쿠키는 계속 유효하다.

## 확인한 기존 동작

- 발급 쿠키는 HttpOnly·SameSite=Lax·path=/·maxAge=43200이며 production에서 Secure를 사용한다. 비밀번호·시크릿은 클라이언트에 전달하지 않는다.
- 로그인 성공/실패는 각각 고정 주소 `/manage`, `/manage/login?error=1`로 이동한다. 임의 `next` 폼 값을 외부 이동 주소로 사용하지 않는다.
- 로그아웃은 쿠키를 지운 뒤 로그인 페이지로 이동한다. 인증이 만료됐어도 로그아웃 쿠키 삭제는 가능하다.
- 실제 관리 서버 페이지 18곳은 본문을 만들거나 관리 데이터를 조회하기 전에 인증을 검사한다. 레이아웃 검사만으로 보호한다고 가정하지 않았다.
- 만료 배너는 보조 안내다. 서버 액션은 별도로 `requireAuth`를 검사한다. 기존 액션 인증·변경 대상 검사와 폼 실패 복구 테스트도 전체 회귀에 포함했다.

설치된 Next.js 16.4.3의 `cookies.md`, `redirect.md`와 인증 가이드의 세션·페이지/액션 경계 관련 규약을 확인했다. 쿠키 수정은 Server Action에 두며 렌더링 중에 쿠키를 쓰거나 지우지 않는다.

## 새 회귀 테스트 70개

### 실제 인증·로그인·로그아웃 코드: 44개

- 실제 Node HMAC을 사용한다. 쿠키 저장소·Next redirect만 대체하고 비밀번호/서명 로직은 대체하지 않는다.
- 기존 정상 쿠키의 호환성, production 옵션, 잘못된 비밀번호의 1500ms 지연, 만료 경계, 잘못된 쿠키 형식·서명·만료값, 설정 없음, 시크릿 변경, 단일 쿠키 조회를 검사한다.
- 실제 로그인 페이지가 반환한 폼 액션으로 성공/실패 경로를 검사한다. 쿠키 발급 후 이동하며, 로그아웃도 삭제 후 이동한다. 삭제 실패는 성공 이동으로 숨기지 않는다.
- 비밀번호·시크릿은 테스트 전용 환경값이며 실제 `.env.local` 값을 읽어 로그인하거나 변경하지 않았다. 테스트의 지연은 가상 시간으로 진행한다.

### 실제 관리 페이지의 경계: 18개

허브, 네 영역의 목록/생성/수정, Studio 안내, Contact, 이력, 사용 안내, 홈페이지 지도를 호출한다. **각 페이지에서** 쿠키 없음·서명 변조·정확히 만료됨·설정 해제의 네 상태를 확인한다. 테스트 18개 안에서 총 72개 상태 조합을 검사한 것이다.

인증 로직은 실제 구현을 사용하고 쿠키·이동·CMS 클라이언트만 대체한다. 거부된 요청에서 관리 데이터 조회나 쓰기 클라이언트 생성이 호출되지 않음을 확인했다.

### 기존 만료 배너: 8개

- SSR 초기 출력, 15분 안내 경계, 남은 분 올림, 정확한 만료 시점, 이미 만료된 경우.
- 새 탭 로그인 링크의 속성, 입력 요소·작성 내용 유지, 같은 탭 자동 이동 없음.
- 서버가 새 만료 시각을 전달할 때 안내 해제, StrictMode 재실행과 화면 해제 후 타이머 정리.

`SessionWatcher` 실행 코드는 변경하지 않았다. 기존 **6개 실제 편집 폼**에서도 인증 실패 뒤 입력·dirty·선택한 파일 요소가 보존되고 재제출 가능한지 확인했다. 이는 기존 회귀 테스트이며 새 테스트 70개에 중복 집계하지 않았다.

## 최종 검증

- 전체 **1,353개 / 57개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과.
- 최종 로컬 빌드에서 관리 경로 18곳에 쿠키 없음/잘못된 쿠키로 요청해 **36/36 로그인 이동** 확인.
- 기존 공개·관리 경로 스모크 **35/35 통과**. 공개 상세 본문·noindex·보안 헤더 포함.
- 로컬 확인 서버는 종료했다. 운영 로그인 제출·CMS 쓰기·환경변수 변경·계정 변경·커밋·배포는 하지 않았다. 임시 공개 테스트 라우트도 추가하지 않았다.

## 보장하지 않는 것과 운영 주의

- 발급·로그아웃 성공 경로는 모의 쿠키 저장소 검사다. 실제 HTTPS 브라우저에서의 쿠키 집행, 운영 로그인, 브라우저 간 세션 공유까지 E2E 검증한 것은 아니다.
- 현재는 서명 쿠키 방식이며 서버 측 세션 폐기 목록이 없다. 로그아웃은 해당 브라우저 쿠키를 지우지만 **복사된 쿠키를 서버에서 즉시 폐기하지는 못한다.**
- **비밀번호 값만 바꿔도 기존 미만료 쿠키는 유지된다.** 유출 대응이나 모든 기기 재로그인이 필요하면 서명용 `MANAGE_SECRET`도 교체해야 한다. 이 문서는 운영 절차 설명이며 실제 설정은 바꾸지 않았다.
- 기존 로그인 실패 지연은 분산/IP별 속도 제한이 아니다. 병렬 시도 차단·다중 사용자 권한·MFA·로그인 감사 로그를 이번에 추가하지 않았다.
- `timingSafeEqual` 사용은 유지했으며 전체 요청의 타이밍 공격 안전성을 측정하거나 보장하지 않는다. [Node.js 공식 주의사항](https://nodejs.org/api/crypto.html#cryptotimingsafeequala-b)도 주변 코드까지 자동으로 안전해지는 것은 아니라고 설명한다.
- 만료 배너는 30초 주기의 클라이언트 안내이며 실제 권한의 근거가 아니다. 새 탭에서 재로그인해도 기존 탭의 배너가 즉시 새 세션을 감지하는 기능은 없다. 서버에서 새 만료 시각을 전달받으면 갱신된다. 미저장 내용 보호를 위해 자동 새로고침은 하지 않는다.
