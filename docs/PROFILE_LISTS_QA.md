# 강사 목록·Crew 링크 저장 보호

## 재현한 문제

- Crew 링크는 행을 다시 만들면서 `_key`·`url`·`iconImage` 외의 원본 필드를 누락시켰다. 같은 행의 URL을 비우면 추가 정보도 함께 자동 제외될 수 있었다.
- 링크마다 주소 검사 직후 아이콘을 올리므로 뒤쪽 주소나 원본이 잘못됐을 때 앞쪽 에셋은 이미 업로드될 수 있었다. 문서 패치가 실패해도 에셋 업로드는 별도 작업이다.
- `linkCount` 누락·빈 값·일부 숫자 표기와 불완전한 행 입력을 빈 목록/빈 행으로 처리하거나, 중복 입력의 첫 값만 선택했다. `linkIconKeep` 누락도 기존 아이콘 제거로 처리했다.
- 강사 소개·커리큘럼은 문자열 배열이며 객체 항목의 `_key`는 없다. 다만 파일 입력을 `String()`으로 변환해 저장할 수 있었고, 중복 입력과 조회 뒤 손상된 원본 목록도 덮어쓸 수 있었다.
- 초기 테스트 59개 중 53개가 수정 전에 실패했다. 모의 저장소 재현이며 운영에서 실제 손실이 발생했다는 뜻은 아니다.

## 수정 정책

### Crew 링크

- 서버 전용 `prepareCrewLinks`로 개수·행 범위·누락/중복 입력·자료형·중복 키·모든 URL·원본 추가 필드를 **전부 검사한 뒤** 아이콘 업로드를 시작한다. 대표 사진도 검사 뒤에만 올린다. 수정과 생성이 같은 사전 검사를 쓴다.
- 개수는 0~10의 일반 십진 정수 표기만 허용한다. 행 주소 필드는 반드시 문자열로 있어야 한다. 키/아이콘 유지 값은 선택 사항이지만, 제공하면 중복 없는 문자열이어야 한다. 선언 개수 밖의 링크 입력을 조용히 버리지 않는다.
- 추가 원본 정보는 임의 병합하거나 클라이언트 값으로 복구하지 않는다. 같은 원본 키를 남긴 행의 추가 필드가 빠질 상황이면 `/admin` 확인 오류를 반환한다. null·false·빈 값·현재 저장기가 출력하지 않는 `_type`도 보호한다. 오류에 원본 값/필드 이름은 노출하지 않는다.
- 유효한 원본 키가 전체 제출 목록에서 빠졌으면 기존 명시적 삭제 계약을 유지한다. 같은 키를 남기고 URL만 비웠을 때는 추가 필드 삭제로 추측하지 않는다. 키 없는 추가 원본 정보나 잘못된 원본 목록도 조용히 버리지 않는다.
- 링크 관련 입력 전체를 생략하면 수정 시 `links`를 패치하지 않는다. 새 문서는 빈 목록으로 만든다. `linkCount=0`은 명시적인 빈 목록이며, 개수 없이 행 필드만 있으면 오류다. 실제 관리 폼은 계속 개수를 포함한 전체 목록을 전송한다.
- 기존 아이콘 유지 필드가 생략되면 같은 행의 원본 아이콘을 유지한다. 명시적인 빈 값은 아이콘 제거로 취급한다. 새 파일/다른 아이콘 선택은 기존 교체 계약을 유지하며 이전 이미지 crop/hotspot을 붙이지 않는다.
- 정상 링크 원본 키와 같은 아이콘의 crop/hotspot/메타데이터는 보존한다. 문서 최상위의 편집 대상 밖 필드는 부분 패치로 유지한다.
- 오류는 해당 `linkUrl_i`에 연결하고, 행이 없거나 전체 목록 문제면 새 `links` 묶음 포커스 대상으로 연결한다. 시각 디자인은 변경하지 않았다.

### 강사 소개·커리큘럼

- 입력이 존재하면 단일 문자열인지 확인한 뒤 줄 목록으로 변환한다. 누락/빈 필수값은 기존 필수 입력 오류로 처리하며, 파일·중복 입력은 업로드 전에 필드별로 거부한다. 생성도 같은 검사를 사용한다.
- 수정 시 서버가 읽은 `about`/`process`가 비정상 자료형이나 문자열 아닌 행을 포함하면 덮어쓰지 않고 `/admin` 확인을 안내한다. 선택적인 누락/null 원본은 기존 규칙을 유지한다.
- 앞뒤 공백·빈 줄 정리와 줄바꿈으로 목록을 나누는 기존 동작은 변경하지 않았다. 모든 문자열의 바이트 단위 동일성을 보장하는 기능은 아니다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽고 적용했다. 판정에는 인증 이후 조회한 서버 원본을 사용한다.

## 검증

새 테스트 **72개**를 추가했다.

- 실제 서버 액션 67개: 추가 필드·아이콘 유지/제거·기본 정보만 저장·명시적 삭제·잘못된 원본, 수정/생성의 뒤쪽 URL 오류와 타입/중복/누락/범위 오류, 강사 파일/중복 입력과 비정상 원본 목록. 오류 때 업로드·패치·생성·캐시 갱신 없음도 확인한다.
- 실제 조회 페이지→폼→액션 5개: Crew 추가 필드 오류와 마지막 행 제거 뒤 원본 오류, 강사 정상 목록/사진/최상위 추가 정보의 반복 저장 왕복, 두 강사 목록의 조회 뒤 손상 오류. 입력·dirty·원본 유지, 오류 요약 클릭 후 실제 DOM 포커스 이동과 refresh 미실행을 검사한다.
- 인증·외부 저장소·라우터는 모의 구현이다. 브라우저 자동화나 실제 CMS 저장 검증은 아니다.

전체 **3,247개 / 93개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 점검도 **37/37 통과**했다. 임시 서버는 종료했다.

현재 공개 Crew 3개·링크 5개·강사 7개를 읽기 전용으로 조회했다. 실제 Crew 사전 검사 차단 0개, 강사 목록의 비정상 자료형 0개였다. 원문·문서 ID·인증 정보는 출력하지 않았으며, 이 검사는 모든 필드의 편집 왕복 동일성을 새로 증명한 검사는 아니다.

## 범위와 한계

- 제출 목록에서 키가 빠진 상황을 사용자의 삭제와 구별하는 새로운 삭제 의도 프로토콜은 추가하지 않았다. 명시적인 사진/아이콘 교체·삭제도 기존 계약을 따른다.
- 유효성 검사가 모두 끝나도 실제 업로드 중 네트워크 실패나 최종 revision 충돌이 생기면 이미 올라간 일부 에셋은 남을 수 있다. 트랜잭션형 업로드나 자동 에셋 삭제를 추가한 작업은 아니다.
- 다른 기본 텍스트·선택값 전체의 강제 변환/중복 검증까지 완료한 것은 아니다. 이번 범위는 강사 두 목록과 Crew 소셜 링크다.
- 운영 데이터 저장·실제 업로드·인증된 브라우저 E2E·커밋·배포는 하지 않았다. 디자인·스키마·환경변수·의존성도 변경하지 않았다.
