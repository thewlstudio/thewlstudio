# 관리자 미리보기·연락처 링크 점검

## 확인한 문제

- Works·Crew 관리 폼의 미리보기는 slug를 경로에 그대로 붙였다. `%`, `?`, `#` 등이 들어간 slug는 실제 공개 주소와 다른 경로·쿼리·fragment로 해석될 수 있었다. 기존 경로 접두사가 고정되어 있었으므로 외부 사이트로 보내는 open redirect나 XSS를 재현한 것은 아니다.
- 연락처 저장 액션은 네이버·인스타그램 호스트를 제한했지만 공개 설정 병합은 일반 HTTPS 여부만 검사했다. Studio·CLI 등 다른 경로에서 수정한 설정에는 같은 서비스 호스트 정책이 적용되지 않았다.
- 전화번호 저장 검사는 숫자 없이 기호만 있는 값과 내부 탭·줄바꿈도 허용했다. 공개 설정은 비어 있지 않은 문자열이면 그대로 썼다.
- 관리자 오디오 미리보기는 URL을 그대로 `src`에 넣고 있었다. 공개 오디오와 같은 URL 검사 경계가 없었으며, 실제 실행형 URL 취약점을 입증한 것은 아니다.

## 반영 내용

### 공개 주소와 미디어 미리보기

- Works·Crew 폼은 공개 목록·사이트맵과 동일한 `publicDetailPath`를 사용해 원본 slug를 한 번 인코딩한다. 문자 그대로의 `%2F`는 `%252F`로 보존하고, 쿼리·fragment 문자는 slug 안에 유지한다.
- 잘못된 slug에는 활성 링크 대신 `/admin`에서 주소를 확인하라는 안내를 표시한다. 생성 폼에는 기존처럼 공개 미리보기 링크를 표시하지 않는다.
- 새 탭 링크의 `noopener noreferrer`와 저장된 내용 기준이라는 안내를 유지한다.
- 오디오 미리보기에도 공개 화면과 동일한 `externalHttpUrl`을 적용한다. 허용되지 않는 URL은 오디오 요소를 만들지 않으며, 편집 중인 제목·아티스트·원본 블록 값을 지우지 않는다.
- 설치된 Next.js 16.4.3의 `node_modules/next/dist/docs/01-app/01-getting-started/04-linking-and-navigating.md`를 읽고 기존 새 탭 앵커 방식을 유지했다.

### 연락처·서비스 URL

`site-settings.ts`의 공통 검사 함수를 저장 액션과 공개 설정 병합에서 함께 사용한다.

| 설정 | 허용 기준 |
| --- | --- |
| 네이버 지도·예약 | HTTPS + `naver.com` 또는 `naver.me`와 그 하위 도메인 |
| 인스타그램 | HTTPS + `instagram.com`과 그 하위 도메인 |
| 블로그 | 일반 HTTPS 주소, 특정 호스트 제한 없음 |
| 전화번호 | 앞뒤 공백 제거 후 5~30자, 숫자 하나 이상, 숫자·공백·`+()-`만 허용 |

- 호스트는 정확히 일치하거나 점으로 구분된 하위 도메인이어야 한다. `notinstagram.com`, `naver.com.evil.example`은 허용하지 않는다.
- 공통 URL 검사는 사용자명·비밀번호 포함 주소, 역슬래시·제어문자·상대경로·실행형 프로토콜도 거부한다. 정상 주소의 쿼리·fragment·인코딩은 임의로 다시 쓰지 않는다.
- 잘못된 저장 입력은 해당 필드 오류로 반환한다. 공개 조회의 잘못된 설정은 기존 정책대로 해당 항목만 기본값으로 대체한다. CMS 원본을 수정하거나 다른 정상 항목을 지우지 않는다.
- Google 지도 iframe은 기존처럼 고정 호스트·경로에 검색어만 인코딩한다. 구현은 바꾸지 않았고 검색어가 다른 매개변수나 iframe 출처를 바꾸지 못하는 회귀 테스트를 추가했다.

## 검증

새 테스트 **91개**를 추가했다.

- 설정 도우미 **48개**: 서비스 도메인·스푸핑·자격증명·URL 형태·전화 서식·항목별 대체·원본 불변성·지도 검색어 인코딩.
- 실제 연락처 저장 액션 **11개**: 오류 시 문서 쓰기/캐시 갱신 없음, 허용 값 저장과 공개 병합 결과 일치. Sanity 쓰기는 모의 구현으로 대체했다.
- 실제 폼·편집기 **32개**: Works·Crew 각각 정상/비정상 slug와 생성 모드, 잘못된 오디오 URL 제외와 정상 URL 보존. DOM 테스트이며 인증된 운영 브라우저 저장 E2E는 아니다.

전체 **1,536개 / 58개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 서버 스모크 **35/35 통과**: 공개 목록·사이트맵의 전체 상세 경로·관리자 비로그인 차단·보안 헤더 확인.

현재 공개 `siteSettings`의 링크 4개와 전화번호는 읽기 전용 조회로 새 규칙에도 유효함을 확인했다. 원문 값이나 인증 정보를 로그에 출력하지 않았고 문서 쓰기도 하지 않았다.

## 범위와 한계

- 전화번호의 실사용·통신사·국가별 유효성이나 E.164 형식을 보장하는 검사는 아니다. 내부 줄바꿈은 거부하고 기존과 같이 앞뒤 공백은 제거한다.
- 허용 도메인은 해당 네이버 장소·예약이나 인스타그램 계정이 실제 사업자의 것인지 보장하지 않는다. 단축 링크와 외부 리디렉션을 따라가 검사하지 않았으며, 블로그는 기존처럼 임의 HTTPS를 허용한다.
- 검사 함수는 URL을 파싱할 뿐 입력된 외부 URL을 서버에서 가져오지 않는다. 새 외부 요청 기능이나 미디어 호스트 제한을 추가하지 않았다.
- 실제 전화 걸기·지도 검색 결과·외부 예약 완료·오디오 재생·운영 CMS 저장은 수행하지 않았다. 기존 기본값으로의 대체는 잘못 저장된 원본 값을 복구하는 기능이 아니다.
- 정상 콘텐츠 디자인·CMS 문서·스키마·환경변수·의존성·커밋·배포는 변경하지 않았다. 새 공개 테스트 경로도 만들지 않았다.
