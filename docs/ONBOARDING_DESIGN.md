# /manage 초심자 온보딩 설계서

목표: **처음 보는 운영자가 사용 설명서를 읽지 않아도** "무엇을 어디서 고치고, 저장하면 어떻게 되고, 실수하면 어떻게 되돌리는지"를 화면 위에서 바로 알게 한다.
참고: 게임 튜토리얼의 말풍선식 안내. 단, 2026년 업무 도구의 원칙(방해하지 않기·건너뛰기·다시 보기·접근성)으로 바꾼다. 연습 모드는 범위에서 제외한다.

## 0. 원칙
1. **방해하지 않는다.** 화면을 막지 않고, 언제든 건너뛰거나 Esc로 닫는다. 한 화면에서 자동으로는 한 번만 보여준다.
2. **다시 볼 수 있다.** 모든 안내 화면에 "이 화면 안내" 버튼. 자동 안내는 끌 수 있다.
3. **실제 화면 위에서** 말한다. 설명은 해당 요소를 가리키고, 3~5단계로 짧게. 한 단계 = 제목 한 줄 + 설명 최대 두 문장.
4. **접근성.** 키보드(→ ← Esc), 스크린 리더(`role="dialog"`, 제목·진행 위치 안내), 움직임 줄이기 설정 존중, 모바일에서는 하단 시트 형태.
5. **데이터를 건드리지 않는다.** 안내는 읽기 전용. 저장소는 브라우저 localStorage뿐(실패해도 화면은 정상).
6. 문구는 해요체, 전문 용어 금지(MANAGE_GUIDE의 문구 원칙).

## 1. 구성 요소 (5가지)

### 1-1. 화면 안내(코치마크 투어)
- 위치: `_components/tour/` — `tours.ts`(내용), `TourProvider.tsx`(상태·자동 시작), `TourOverlay.tsx`(스포트라이트·말풍선).
- 대상 지정: 화면 요소에 `data-tour="이름"` 속성. 단계의 대상이 화면에 없으면(예: 항목이 적어 검색창이 숨김) **그 단계를 건너뛴다**.
- 자동 시작: 화면 진입 700ms 뒤, 이 투어를 아직 안 봤고 "자동 안내 끄기"가 아니며 화면에 대상이 1개 이상 있을 때. 시작 시 `localStorage["wls_tour_seen_v1"]`에 투어 id 기록.
- 수동 시작: 상단 "이 화면 안내" 버튼(안내가 있는 화면에만 표시).
- 말풍선: 제목, 본문(`**강조**` 지원), 진행 `2 / 5`, [이전] [다음/완료] [건너뛰기], 첫 단계에 "앞으로 자동으로 보지 않기".
- 배치: 대상 아래 → 위 → 오른쪽 순으로 화면 안에 들어가는 곳. 대상이 화면 밖이면 스크롤. 리사이즈·스크롤 때 위치 재계산.
- 스포트라이트: 대상 둘레에 6px 여백의 밝은 테두리, 바깥은 55% 어둡게. **클릭은 막지 않음**(포인터 이벤트 통과) — 단, 말풍선 밖 클릭은 아무 일도 하지 않는다.

### 1-2. 시작 체크리스트 (허브)
- "처음 설정 n/5" 카드(접기 가능). 항목은 **행동이 일어나면 자동 체크**:
  1. 사용 안내 둘러보기 — `/manage/help` 방문
  2. 연락처·링크가 맞는지 확인 — `/manage/contact` 방문
  3. 홈페이지 소개 문구 저장해 보기 — Contact 저장 성공
  4. 강사·Crew·Works·Studio 중 하나 고쳐서 저장 — 해당 영역 저장 성공
  5. 홈페이지에서 결과 확인 — 허브의 "홈페이지 보기" 클릭
- 5/5가 되면 축하 문구와 "숨기기". 숨긴 뒤에도 "사용 안내" 페이지에서 다시 열 수 있다.
- 저장소: `wls_checklist_v1`(완료 항목 id 배열), `wls_checklist_hidden_v1`.

### 1-3. 홈페이지 지도 (`/manage/map`)
- 홈페이지 각 페이지(홈·Class·Works·Crew·Studio·Contact·공통 머리말/꼬리말)를 **단순 와이어프레임**으로 그리고, 번호 핀 ①②…을 붙인다. 핀을 누르거나 아래 표의 줄을 누르면 해당 수정 화면으로 이동.
- 각 핀 설명 형식: "홈 첫 화면 소개 제목 → Contact › 홈페이지 소개 문구".
- 실제 화면을 여는 "홈페이지에서 보기 ↗" 링크 포함. 허브 카드 아래와 사용 안내 상단에서 연결.

### 1-4. 빈 화면 안내
- 목록이 0개일 때(휴지통 제외): 아이콘 + "아직 ○○이 없어요" + 한 줄 설명 + [+ 첫 ○○ 만들기] 버튼. 쓰기 불가 상태면 버튼 대신 안내 문구.

### 1-5. 칸 옆 "?" 설명, 강조 문구, 현황 수치
- `HelpTip`: 작은 "?" 버튼 → 팝오버(제목·본문·선택 예시). `aria-expanded`, Esc/바깥 클릭으로 닫기, 포커스 복귀. `Section`에 `help` 속성으로 연결.
- 힌트 문구의 `**강조**`를 굵게 표시(Field·Section hint 공통).
- 허브 카드에 **현황 수치**(예: 강사 7명 · 공개 7 / Works 8개 / 연습실 4·로비 1).

## 2. 투어 내용 (화면별, 최대 6단계)
| 투어 id | 화면 | 단계(대상 → 말) |
|---|---|---|
| hub | /manage | 항목 카드("고칠 항목을 고르세요, 숫자는 등록된 개수") → 홈페이지 보기("저장 전에는 홈페이지가 바뀌지 않아요") → 최근 수정 → 사용 안내/이 화면 안내 버튼 |
| list | 강사·Crew·Works·Studio 목록 | + 새 항목 → 검색·필터(있을 때) → 첫 줄(눌러서 수정, "n시간 전 수정") → 순서(▲▼·끌기, Works 제외) → 휴지통 보기 |
| form | 각 수정/새로 만들기 화면 | 미리보기(있을 때) → 첫 입력 영역(빨간 별=필수) → 사진 영역(고르기·자르기) → 저장 막대(저장하기=즉시 반영, Ctrl+S, 변경 버리기) → 변경 이력 → 삭제·비공개(있을 때) |
| works-blocks | 작업물 수정 | 상세 페이지 블록(추가·접기·순서) |
| contact | /manage/contact | 위치·연락처 → 지도(주소만) → 링크 → 홈페이지 소개 문구 |
| studio-info | /manage/studio/info | 서비스·장비·멤버십 카드 접기/펼치기 → 이용 안내 |
| help·map·history | 각 화면 | 1~2단계 |

## 3. 데이터·저장소
- 모두 브라우저 localStorage, 키 접두사 `wls_`: `tour_seen_v1`, `tour_auto_off_v1`, `checklist_v1`, `checklist_hidden_v1`, 기존 `manage_guide_dismissed`.
- 버전 접미사(`_v1`)를 올리면 전원에게 다시 보여줄 수 있다(새 기능 안내용).
- 서버·Sanity 변경 없음.

## 4. 구현 단계와 검증
| 단계 | 내용 | 검증 |
|---|---|---|
| P1 | 설계서, 강조 문구, 빈 화면 안내, 허브 현황 수치, HelpTip(+주요 Section에 적용) | 목록 0건 상태 시험, 강조·팝오버 키보드 동작, 린트·빌드 |
| P2 | 투어 엔진 + 화면별 투어 + `data-tour` 부착 + "이 화면 안내" 버튼 | 자동 시작·건너뛰기·다시 보기·대상 없는 단계 건너뛰기, 모바일 폭, 키보드 |
| P3 | 시작 체크리스트(자동 체크) | 방문·저장·클릭 이벤트로 체크, 새로고침 후 유지 |
| P4 | 홈페이지 지도 | 핀→수정 화면 이동, 모바일 폭 |

각 단계마다 `tsc`·`eslint`·`build`, 로컬 화면 시험, 별도 커밋·푸시·배포 확인.

## 5. 범위 밖 / 한계
- 연습 모드(샌드박스), 저장 전 미리보기·게시 단계 분리, 다중 사용자·권한, 영상 안내는 이번 범위에 없다.
- 브라우저 localStorage 기반이라 **기기·브라우저마다 따로** 기록된다(다른 기기에서는 안내가 다시 나온다).
- 실제 초심자 관찰 시험은 사람이 해야 한다.
