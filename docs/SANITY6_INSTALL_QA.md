# Sanity 6 설치 복구·Node 기준·CSP 점검

## 최초 수정 (70f64d1)

- 프로젝트 `engines.node`를 Sanity 6의 최소 요구사항인 `>=22.12`로 변경하고 잠금 파일의 루트 정보와 설치 가이드도 맞췄다. `.nvmrc`의 22와 CI의 해당 파일 참조는 유지한다.
- 실제 실패 CI와 같은 Node 22.23.4·npm 10.9.9를 임시 도구로 준비했다. 작업 중인 node_modules를 삭제하지 않고, 추적 파일만 복사한 별도 임시 사본에서 잠금 파일을 재생성했다. 환경변수 파일이나 계정 자격증명은 복사하지 않았다.
- 누락된 `@emnapi/core@2.0.0-beta.2`, `@emnapi/runtime@1.11.3`을 추가했다. 기존 잠금 패키지의 버전 변경이나 삭제는 없으며, 나머지는 npm이 재계산한 peer/optional 설치 메타데이터다.
- 공개 보안 헤더의 경로 제외를 정확한 `/admin` 또는 `/admin/` 하위에만 적용했다. `/administrator`·`/admin-help` 같은 일반 주소에도 공개 CSP를 적용하며, Studio의 기존 글꼴 CDN 허용과 실행 예외는 유지한다. 새로운 출처나 스크립트 예외는 추가하지 않았다.
- 남은 취약점은 [의존성 보안 기록](DEPENDENCY_SECURITY.md)의 2026-11-17 항목에 세 경로를 모두 기록했다. 강제 자동 수정·메이저 재변경은 하지 않았다.

## 최초 로컬 검증

- 설치된 Next.js의 headers 문서와 실제 경로 매처로 회귀 검사 10개를 추가했다. 수정 전 일반 주소 4개가 헤더 규칙과 매칭되지 않음을 재현했다. Node·잠금 파일·CI 기준 검사 2개도 추가했다.
- CI와 동일한 도구 버전으로 Linux 대상 `npm ci --dry-run --ignore-scripts` 설치 계획 검사 통과. 이는 실제 Linux 실행이나 원격 CI 통과를 뜻하지 않는다.
- 비어 있던 별도 사본에서 실제 `npm ci` 통과(현재 기기의 운영체제). 그 사본의 새 의존성만으로 타입 검사·ESLint·전체 **5,188개 / 123개 파일**·프로덕션 빌드를 통과했다. 실제 로그인 정보 대신 기존 CI의 테스트 설정만 사용했다.
- 새 빌드의 로컬 스모크 **42/42**, 실제 HTTP 보안 헤더 검사 **7/7**을 통과했다. 일반 주소 404에도 CSP·프레임 보호·nosniff가 있으며 Studio에서만 글꼴 CDN과 기존 실행 예외가 허용됨을 확인했다. 이는 실제 Studio 계정 로그인/편집 검증을 뜻하지 않는다.
- 취약점 전체/개발 제외 조회는 각각 **17건(High 2·Moderate 15)**이다. 강제 수정하지 않은 추적 대상이며 설치 복구로 취약점이 모두 해소됐다고 표현하지 않는다.

## 최초 배포 결과와 후속 수정

- 승인 후 `70f64d1`을 커밋·푸시했고 GitHub CI [44040096301](https://github.com/thewlstudio/thewlstudio/actions/runs/44040096301)은 설치·타입·린트·테스트·빌드·스모크까지 성공했다.
- Vercel 배포는 실패했다. 제공된 로그에서 `>=22.12` 때문에 프로젝트 설정의 24 대신 Node 26을 선택한 사실과, `vitest.config.ts`의 `esbuild.jsx`에 대한 TS2769 오류가 확인됐다. Node 26 자체가 실패 원인이라고 단정하지 않는다.
- 로컬에서 Vite의 선택 의존성인 `esbuild` 타입을 찾지 못하도록 한 읽기 전용 모의 검사로 같은 TS2769 오류를 재현했다. 이는 Vercel의 실제 의존성 설치 상태를 직접 확인한 결과는 아니다.
- 사용자 승인에 따라 프로젝트와 잠금 파일의 Node 정책을 `26.x`, `.nvmrc`를 26으로 맞췄다. CI·백업은 기존의 `.nvmrc` 참조를 유지하며, Sanity 자체의 최소 Node 요구사항과 프로젝트 정책을 구분한다.
- Vite 8 권장 방식인 `oxc.jsx.runtime: automatic`으로 전환했다. 타입 검사를 생략하거나 테스트 파일을 빌드 검사에서 제외하지 않는다.
- Node 26 새 설치에서 브라우저 테스트 8개가 실패했다. Vitest가 이미 존재하는 Node의 Web Storage를 jsdom 저장소로 교체하지 않아 생긴 테스트 환경 충돌이다. jsdom 테스트에서만 해당 창의 `localStorage`·`sessionStorage`를 사용하도록 초기화하고 회귀 검사를 추가했다. 실제 서버·브라우저 코드나 Node 환경 테스트의 저장소는 바꾸지 않는다.
- 후속 변경의 Node 26 검증·배포 상태는 아래에 별도 기록한다. 기존 운영 사이트의 스모크 42/42 성공은 새 변경이 배포됐다는 뜻이 아니다.
- Studio 계정 로그인 후 편집, 실제 저장·비공개 미리보기·삭제/복원은 별도 확인 대상이다. 이 작업에서 운영 문서를 쓰거나 삭제하지 않았다.

## Node 26 후속 로컬 검증

- 추적 소스와 이번 변경만 복사한 별도 사본에서 Node **26.13.1**·npm **11.6.2**로 실제 `npm ci`에 성공했다. 기존 작업 폴더의 의존성이나 환경변수 파일은 복사하거나 덮어쓰지 않았다. 패키지 버전 변경 없이 잠금 파일의 프로젝트 Node 정책만 수정했다.
- `esbuild` 타입을 찾지 못하는 동일한 조건에서 원래 설정은 TS2769가 발생하고 Oxc 설정은 오류가 없음을 읽기 전용 TypeScript 검사로 확인했다.
- 타입 검사(증분 캐시 미사용)·ESLint·전체 **5,192개 / 124개 파일**·프로덕션 빌드가 통과했다. jsdom 테스트가 Node 저장소가 아닌 현재 창의 저장소를 사용하며, 테스트가 끝나면 원래 전역 속성을 복원한다.
- Node 26으로 실행한 새 로컬 빌드의 스모크 **42/42**를 통과했다. 공개·상세 페이지, 관리 화면 로그인 보호, 미리보기 차단, 캐시 정책, 보안 헤더를 확인했다. 실제 Sanity 문서는 수정하지 않았다.
- 남은 비차단 경고: Vite 설정 파일의 향후 native-loader 전환 안내, 의존성 `debug`의 서버 측 `localStorage` 기능 탐지 시 Node 경고. 경고를 숨기거나 서버에 공유 저장소 파일을 추가하지 않았다.
- 이 후속 변경의 원격 CI·운영 배포 성공 여부는 로컬 검증과 별도로 확인해야 한다.
