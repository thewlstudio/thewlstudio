# 상세·공유 정보·사이트맵의 비공개 항목 노출 경계

## 확인 결과

- Works·Crew의 공개 목록/상세/사이트맵은 같은 공개 필터를 사용한다. 일반 방문에서는 `isActive: false`를 제외하고, `trashed: true`는 인증된 미리보기에서도 제외한다. 기존 호환 정책인 공개 여부 필드 누락 시 공개도 유지한다.
- 상세 본문과 `generateMetadata`가 모두 같은 `sanityFetch`와 영역 태그를 사용한다. 조회 결과가 없으면 둘 다 `notFound()`로 중단하므로 문서별 OG/Twitter·JSON-LD를 반환하지 않는다. 이번에 이 연결의 추가 노출 결함은 확인하지 않았다.
- 정적 경로 생성과 사이트맵은 인증/미리보기 상태와 무관하게 `includeHidden: false`를 직접 전달한다.
- `/manage`의 저장·삭제·복원은 영역 태그와 상세/사이트맵 경로를 갱신한다. 캐시 연결과 Studio 직접 변경의 한계는 기존 [캐시 갱신 점검](CACHE_INVALIDATION_QA.md)을 재확인했다.

## 발견한 누락과 수정

- 기존 미리보기 설계에는 검색 방지(`noindex`)가 있었지만 루트·공개 상세 메타데이터에 구현되지 않았다. 이것만으로 비로그인 사용자가 숨김 문서에 접근할 수 있다는 의미는 아니다. 조회 인증과 별개로 방어 장치가 빠진 것이다.
- 루트의 기존 정적 메타데이터를 기본값으로 유지하고, `generateMetadata()`에서 **인증된 관리자 미리보기일 때만** `robots: { index: false, follow: false, nocache: true }`를 추가한다.
- 하위 공개 목록/상세가 이 요청별 robots를 덮어쓰지 않는지도 검사한다. 정상 공개 요청에는 noindex를 추가하지 않으며, 기존 제목·정규 주소·공유 이미지·일반 공개 ISR은 유지한다. 관리자 영역의 기존 noindex는 그대로다.
- robots 메타데이터는 검색엔진에 대한 지시이지 인증이나 HTTP 캐시 제어가 아니다. 기존 미리보기 조회 인증·응답 캐시 정책을 대체하지 않는다.

## 회귀 검증

- 새 테스트 **47개**를 추가했다. 운영 문서 대신 가상 발행 문서를 사용한다.
- Sanity 패키지가 직접 의존하는 설치본 `groq-js`를 해당 패키지 기준으로 찾아 실제 쿼리 문자열을 파싱/평가한다. 질의 필터를 JavaScript 조건문으로 흉내 내지 않았으며 새 의존성이나 운영 데이터는 추가하지 않았다. Sanity의 향후 의존성 구조가 바뀌면 테스트 도구 로딩도 검토해야 한다.
- 실제 `sanityFetch`·세션 서명/만료 검사·상세 서버 페이지·메타데이터·사이트맵을 연결했다. SDK 네트워크 fetch와 Next 쿠키 저장소, 화면 하위 클라이언트 컴포넌트만 대체했다.
- 본문/OG/Twitter/JSON-LD: Works·Crew × 일반/인증된 미리보기/정확히 만료/로그아웃 × 공개/비공개/휴지통/기존 필드 누락 = 32개.
- 정적 경로/사이트맵: 두 영역 × 네 요청 상태 = 8개. 미리보기 이후 로그아웃된 다음 호출에서 숨김 문서를 재사용하지 않는 검사 2개.
- 루트 요청별 robots·기존 공유 정보 유지·일반 요청 오염 방지 5개. 기존 공개 영역 메타데이터 테스트에도 robots 상속 검사를 보강했다.
- 전체 **4,770개 / 113개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 기존 공개 1시간 ISR과 정적 경로 생성도 유지됐다.
- 로컬 프로덕션 스모크 **41/41 통과**. 홈·Class·Works/Crew 목록·Works/Crew 상세 총 6경로를 일반 → 인증된 미리보기 → 일반 순서로 요청한 **18개 응답**에서 미리보기만 noindex이며 해당 응답은 private/no-store임을 확인했다. 일반 페이지로 검색 방지가 남지 않았다.
- 사이트맵의 일반/미리보기 쿠키 요청은 **URL 목록이 동일**했다. 처음 전체 XML을 비교했을 때에는 고정 페이지의 `lastmod: new Date()`가 재생성 시각으로 달라졌으므로, 이 노출 검사는 URL 집합으로 비교했다. 생성 시각을 실제 콘텐츠 수정일로 판단하지 않는다.
- 없는 Works/Crew 상세를 일반 브라우저/공유 봇 User-Agent로 요청한 **4개 응답**은 모두 404와 noindex였다. 운영 항목을 숨기거나 삭제해 테스트하지 않았다. 임시 로컬 서버는 종료했다.

## 범위와 한계

- 모의 SDK 대신 실 Sanity 서버의 모든 데이터셋 권한·perspective 동작을 재현한 것은 아니다. 가상 데이터는 발행 문서이며 `drafts.*`/콘텐츠 릴리스를 포함하지 않는다. 운영 비공개 문서 내용이나 식별자는 조회·출력하지 않았다.
- 인증된 미리보기 응답에는 해당 항목의 메타데이터/JSON-LD가 본문과 함께 있을 수 있다. 사이트맵에는 포함하지 않으며, 해당 HTML에는 noindex를 적용한다. 이를 공개 검색용 산출물로 배포하지 않는다.
- 숨기기는 공개 데이터셋의 발행 문서를 비밀 저장소로 만드는 기능이 아니다. 이미 전달된 화면과 외부 검색/공유 플랫폼의 이전 캐시를 회수하지 못한다.
- Studio·CLI에서 직접 변경하면 관리자 액션의 즉시 갱신을 거치지 않는다. 현재 공개 1시간/사이트맵 24시간 재검증 설정이며, 실제 갱신은 요청·조회 성공 여부에 따른다. 외부 변경 즉시 반영 webhook은 이번에 추가하지 않았다.
- 운영 저장·업로드·환경변수 변경·커밋·배포는 하지 않았다.
