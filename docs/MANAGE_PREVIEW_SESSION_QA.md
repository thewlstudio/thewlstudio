# 미리보기의 세션 만료·로그아웃 경계

## 확인한 결함

- `/manage/preview` 진입은 인증을 확인했지만, 이후 `sanityFetch`의 `includeHidden`과 미리보기 안내 띠는 `draftMode().isEnabled`만 확인했다.
- 관리자 세션은 12시간 만료/로그아웃이 가능하지만 미리보기 쿠키는 별도다. 기존 로그아웃도 관리자 쿠키만 삭제했다. 따라서 미리보기 쿠키가 남은 요청은 유효한 관리자 세션이 없어도 홈페이지 조회에서 비공개 항목을 포함할 수 있었다.
- 실제 세션 서명 검증과 모의 CMS 조회를 연결한 회귀 테스트로, 수정 전 11개 실패를 확인했다. 운영 비공개 문서를 조회하거나 내용·식별자를 출력해 재현하지 않았다.

## 수정

- 서버 전용 `isManagedPreview()`를 도입해 미리보기 쿠키와 현재 유효한 관리자 세션을 모두 요구한다. 세션의 서명·정확한 만료 시각·설정 해제 검증은 기존 인증 함수를 재사용한다.
- `sanityFetch`와 미리보기 안내 띠가 같은 판정을 사용한다. 쿠키만 남았거나 세션이 만료되면 비공개 항목을 포함하지 않고 안내 띠도 표시하지 않는다. 호출자가 `includeHidden: true`를 넘겨도 이 판정이 우선한다.
- 미리보기 쿠키가 없는 일반 공개 요청은 관리자 쿠키를 읽지 않는다. 공개 페이지의 ISR을 전부 동적으로 바꾸지 않으며, 공개 조회의 기존 3,600초/태그 정책과 인증된 미리보기의 재검증 0을 유지한다.
- 로그아웃은 관리자 쿠키 삭제 → 미리보기 종료 → 로그인 화면 이동 순서다. 쿠키 변경 실패를 성공 이동으로 숨기지 않는다.
- 서버 렌더링 중에는 쿠키를 지우지 않는다. 권한 없는 남은 미리보기 쿠키는 조회 권한으로 인정하지 않으며, 명시적인 종료나 로그아웃 경로에서 정리한다.

## 검증

- 새 통합 회귀 테스트 **15개**: 정상 미리보기, 일반 공개 요청의 인증 조회 생략, 세션 없음·만료·변조·시크릿 교체/해제·비밀번호 해제, 조회 사이 만료, 인증 조회 실패, 로그아웃 순서, 미리보기 종료 실패 후 권한 차단.
- CMS 응답과 Next 쿠키 저장소만 모의 실행한다. 인증 함수와 홈페이지 조회·안내 띠·로그아웃 액션은 실제 코드를 연결한다. 기존 클라이언트/안내 띠 테스트도 인증 조건을 갖추도록 갱신했다.
- 전체 **4,723개 / 112개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 공개 페이지의 기존 1시간 ISR과 정적 경로는 유지됐다.
- 로컬 프로덕션 스모크 **41/41 통과**. 테스트용 인증 설정을 서버 프로세스에만 주입한 HTTP 비교 **5개**도 통과했다: 유효한 세션+미리보기, 미리보기 쿠키만 남음, 만료된 세션, 잘못된 세션, 미리보기 없는 유효한 세션. `/class`의 상태 코드·안내 띠 유무와 미리보기 쿠키 요청의 비캐시 응답을 확인했으며 문서 내용이나 쿠키 값은 출력하지 않았다.
- HTTP 비교는 안내 띠와 응답 캐시 경계를 확인한다. 실제 비공개 항목이 들어 있는 운영 데이터를 저장하거나 그 내용으로 비교하지 않았다. 비공개 조회 매개변수의 차단은 모의 CMS와 실제 인증 함수를 연결한 테스트에서 확인했다. 로그아웃 액션의 쿠키 변경은 모의 저장소에서 검증했다.

## 범위와 한계

- 만료/로그아웃 후의 새 서버 조회를 차단한다. 이미 브라우저에 전달된 화면·스크린샷을 회수하거나, 열린 탭을 만료 시각에 자동으로 지우는 기능은 아니다.
- 공유 비밀번호와 서명 쿠키의 기존 인증 방식은 바꾸지 않았다. 탈취된 유효 세션을 서버 저장소에서 개별 폐기하는 기능은 추가하지 않았다.
- 여기서 비공개 항목은 공개 데이터셋에 발행된 문서의 `isActive` 표시 제어를 뜻한다. Sanity 초안(`drafts.*`) 조회나 데이터셋 접근 권한을 새로 제공하는 것이 아니며, 민감 자료를 저장할 보안 경계로 해석하면 안 된다.
- 운영 저장·업로드·환경변수 수정·커밋·배포는 하지 않았다.
