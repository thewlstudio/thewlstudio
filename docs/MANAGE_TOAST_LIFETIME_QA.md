# 관리자 알림의 주소 정리·표시 수명 점검

## 확인한 문제

- 생성 완료 안내에서 `created=1` 표시를 지울 때 주소의 해시(현재 섹션 위치)까지 빠졌다. 다른 검색 조건과 함께 현재 섹션도 보존하도록 보완했다. 새 탐색 기록이나 서버 요청은 만들지 않는다.
- 개발 모드 StrictMode의 effect 재실행에서 첫 알림의 만료 타이머가 정리된 뒤 다시 예약되지 않아, 생성/삭제 안내가 정해진 시간 뒤 사라지지 않는 경우를 재현했다.

## 수정과 유지한 정책

- 알림 생성 때 기존과 같은 만료 시점(일반 안내 5초, 되돌리기가 있는 안내 10초)을 기록한다. 타이머는 실제 표시 목록에서 예약하고 effect 정리 때 모두 해제한다.
- effect 재실행이나 다른 알림 추가로 타이머를 다시 예약하더라도 원래 만료 시점까지 남은 시간만 사용한다. 먼저 표시한 알림의 수명을 늘리지 않는다.
- 기존 최대 3개 표시 정책은 유지한다. 목록에서 밀려난 알림, 직접 닫은 알림과 사라진 제공자의 타이머도 정리한다.
- 생성 표시를 지울 때 기존 History API 방식에 해시 보존만 추가했다. 설치된 Next App Router가 외부 `replaceState` 호출에서 자체 탐색 정보를 복사하고 라우터의 URL을 동기화하므로, 기존 `null` 호출을 유지한다. 프레임워크 내부 상태를 직접 복제하거나 해석하는 코드는 추가하지 않았다. 임의의 사용자 정의 history.state 전체 보존을 새로 제공하는 변경은 아니다.
- 저장/복원 요청과 후속 화면 갱신의 공유 쓰기 잠금은 변경하지 않았다. 알림이 사라졌다고 이미 전송한 요청이 취소됐다고 가정하지 않는다. 서버 처리 결과를 확인하지 못한 경우를 성공으로 바꾸거나 자동 재시도하지 않는다.

## 기준과 검증

- 설치된 Next.js 16.4.3의 탐색 가이드 중 Native History API 설명, useRouter 문서와 `dist/client/components/app-router.js`의 실제 외부 History API 연동을 확인했다. 전체 history.state를 그대로 전달하면 프레임워크 내부 호출로 취급되는 경로가 있어 그 방식을 채택하지 않았다.
- 회귀 검사 9개를 추가했다. 수정 전 섹션 주소 누락과 StrictMode의 생성/삭제 알림 만료 실패 등 3개 실패를 확인했다.
- 해시·나머지 검색 조건·중복 검색 값·탐색 기록 길이 보존, StrictMode의 단일 생성 안내와 5초/10초 만료, 기존 만료 시점 유지, 표시 한도와 타이머 정리를 검사한다.
- 미저장 변경 경고 취소 시 알림 유지/복원 미실행, 서로 다른 되돌리기를 같은 순간 눌러도 모의 요청 한 번만 전송하는지 확인했다. 기존 저장·삭제·복원·화면 갱신 실패 안내와 지연 중 공유 잠금 검사도 통과했다.
- 전체 **5,176개 / 121개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 최종 빌드의 읽기 전용 로컬 스모크 **42/42 통과** 후 임시 서버를 종료했다. DOM과 모의 복원 함수·모의 라우터·가짜 시계를 사용했으며 운영 문서는 생성/저장/삭제/복원하지 않았다.

## 범위와 한계

- 실제 로그인 후 운영 문서를 생성하는 종단 테스트나 모든 브라우저의 알림 음성 낭독을 수행한 결과는 아니다.
- 알림 디자인·문구·표시 개수·대기 시간·인증·데이터 저장 규약은 유지했다. 새로고침 실패나 통신 결과 불확실성의 기존 안내 정책도 바꾸지 않았다.
- 운영 데이터·업로드·환경변수·의존성·스키마·커밋·배포는 변경하지 않았다.
