# Studio 배열 원본 추가 필드 보호

## 확인한 결함

- 공간 가격과 안내의 서비스·장비·멤버십은 제출 값으로 행 객체를 다시 만들기 때문에, 서버 원본에 편집기가 지원하지 않는 필드가 있으면 다른 내용만 저장해도 함께 빠질 수 있었다.
- 공간 가격의 기존 `_key`가 `new-`로 시작하면 새 임시 키로 오인해 다시 발급했다.
- 초기 회귀 테스트 37개 중 26개가 수정 전에 실패했다. 이는 모의 저장소에서 재현한 결함이며 실제 운영 데이터가 손실됐다는 뜻은 아니다.

## 반영 내용

- 서버 전용 `studio-array-fields.ts`에 실제 재작성 필드를 정의했다. 유지할 원본 행에 지원하지 않는 필드가 있으면 사진 업로드·패치 전에 저장을 거부한다. 원본 필드를 임의 병합하거나 클라이언트의 확장 값을 저장하지 않는다.
- 값이 null·false·빈 문자열이어도 원본 정보로 취급한다. 현재 저장기가 출력하지 않는 행의 `_type`도 보호한다. 오류에는 고정 묶음 이름과 `/admin` 안내만 포함하며 원문 값·필드 이름은 노출하지 않는다.
- 유효한 원본 키가 제출 전체 목록에서 빠진 경우는 기존 명시적 삭제 계약을 유지한다. 키 없는 원본은 위치로 대응시키거나 삭제로 추측하지 않는다. 가격 칸을 비워 자동 제외되기 전의 원본 행으로 검사하므로, 같은 키를 남긴 채 비워도 추가 정보가 유실되지 않는다.
- 서비스·장비·멤버십은 고정 문서 저장 함수에 선택적 원본 검증 콜백을 전달한다. 함수가 한 번 읽은 원본을 검사한 뒤 그 `_rev`로만 패치한다. 검사 후 새 문서를 다시 읽어 보호를 우회하지 않는다. Contact 등 기존 호출은 변경하지 않았다.
- 공간 가격의 키 생성에는 같은 서버 가격 배열을 전달한다. 기존 `new-` 키는 보존하고 새 임시·미지정 키만 발급한다. 새 공간 생성의 키 발급과 빈 행 정리는 유지한다.
- 오류는 기존 `prices`/`services`/`equipment`/`memberships` 요약에 연결된다. 입력·미저장 상태·서버 문서와 revision은 유지하고 성공 refresh는 실행하지 않는다.
- 사진은 교체하지 않는 한 원본 객체 전체를 보존하는 기존 처리를 유지한다. 사진 내부 메타데이터를 새 필드 모델로 재해석하지 않았다. 문서 최상위의 편집 대상 밖 필드도 기존 부분 패치로 유지된다.

설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/01-directives/use-server.md`를 읽고 적용했다.

## 검증

새 회귀 테스트 **60개**를 추가했다.

- 실제 저장 액션 55개: 네 배열의 추가 값·미지원 `_type`·키 없음·특수 필드명·명시적 삭제·클라이언트 확장 값 무시·기존 키 보존, 가격 자동 제외 방지, 안내 단일 원본 조회와 revision 충돌 거부.
- 실제 폼→액션 3개: 안내의 세 배열에서 오류 시 입력·dirty·오류 연결 대상·문서 유지, 패치/생성/refresh 미실행.
- 실제 조회 페이지→폼→액션 2개: 공간 가격 추가 필드 오류의 입력/원본 유지, `new-` 가격 원본 키의 반복 저장 왕복.
- 인증·저장소·라우터는 모의 구현이다. 기존 사진의 참조·crop·메타데이터 보존 테스트도 함께 통과했다.

전체 **3,175개 / 92개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 로컬 프로덕션 경로 스모크도 **37/37 통과**했다. 점검용 서버는 종료했다.

공개 CMS를 읽기 전용으로 조회해 **공간 5개·사진 13개·Studio 안내 1개**를 확인했다. 실제 보호 함수를 메모리에서 실행했으며 공간 차단 0개·안내 차단 0개였다. 원문·문서 ID·토큰은 출력하지 않았다. 이 조회는 원본 추가 필드 검사이며 모든 값의 편집 왕복 동일성을 새로 증명한 검사는 아니다.

## 범위와 한계

- 지원하지 않는 추가 필드를 편집하거나 복구하는 기능이 아니라 조용한 손실을 막는 보호다. 해당 오류가 나면 입력을 보관하고 `/admin`에서 원본을 확인해야 한다. 검사 기준을 끄거나 필드를 임의로 제거해 우회하지 않는다.
- 전체 제출 목록에서 키가 빠진 상황을 사용자의 삭제와 구분하는 새로운 삭제 의도 프로토콜은 추가하지 않았다. 사진의 명시적 교체·삭제 역시 기존 계약을 따른다.
- 새 필드를 지원할 때는 실제 직렬화기·편집 모델·소유 필드 정의·왕복 테스트를 함께 변경해야 한다.
- 운영 저장·실제 업로드·인증된 브라우저 E2E·커밋·배포는 하지 않았다. 디자인·스키마·환경변수·의존성도 변경하지 않았다.
