# 공개 목록의 조회 실패·잘못된 데이터 처리

## 확인한 문제와 수정

- Works·Crew·Class는 SDK 응답을 타입 선언만 믿고 클라이언트에 넘겼다. `null` 행, 객체 형태의 이름/소개, 문자열로 잘못 들어온 소개 목록 등이 렌더링이나 모달 클릭 시 오류를 일으킬 수 있었다.
- 서버 전용 `readPublicList`에서 실제 배열·직접 존재하는 행과 화면에서 사용하는 필드의 자료형을 확인한다. Works·Crew·강사의 중복 식별값도 거부한다. 깨진 행을 삭제해 정상 목록이나 “등록된 항목 없음”으로 꾸미지 않는다.
- Works·Crew·Class의 비정상 응답은 고정된 영역 이름의 오류로 중단하고 기존 오류 화면으로 전달한다. 네트워크 오류도 정상 빈 배열로 바꾸지 않는다. Works 페이지 번호/정규 주소 계산은 같은 검증된 목록을 사용한다.
- 정상 빈 목록은 그대로 전달한다. 정상 원본 행의 값·순서·추가 정보·객체는 바꾸지 않고, 정상적인 선택 필드 누락/null은 기존 빈 표시 정책을 유지한다. Works·Crew의 기존 잘못된 상세 주소 제외 정책, 공개 필터·조회 태그·캐시는 유지한다.
- Crew의 링크 목록, Class의 소개·과정 목록과 이미지 참조를 화면에 넘기기 전에 확인한다. 이미지 URL은 기존 URL 생성기로 생성 가능한지만 확인하며 업로드·에셋 변경·URL 네트워크 조회는 하지 않는다. 외부 링크와 이미지 도메인의 기존 표시 차단/대체 정책은 바꾸지 않았다.

## Studio의 유지한 정책

- 공간 배열의 이름·가격·사진·특징·안내와 공간 종류를 확인하고, 안내 문서도 `mergeInfo`에 넘기기 전에 자료형을 확인한다. 문서 없음의 정상 응답은 `null`이며, 성공처럼 반환된 비정상 응답은 오류로 기록한다.
- 기존 **조회 실패 시 예비 방/로비·안내 사용** 정책은 유지했다. 잘못된 공간 응답도 catch 안에서 감지해 같은 대체 경로를 사용하며, 안내 실패가 정상 공간 조회를 없애지 않도록 영역을 분리한다.
- 정상 빈 공간 목록에는 예비 방/로비를 되살리지 않는다. 안내의 명시적인 빈 목록·빈 문구, 누락 필드만 기본값으로 채우는 기존 계약도 유지한다.
- catch에서는 `unstable_rethrow`를 먼저 호출한다. `notFound`/리다이렉트/요청 시 렌더링 같은 Next 내부 중단 신호를 정상 예비 데이터로 삼키지 않는다.

## 오류 화면의 재조회

- 설치된 Next.js 16.4.3의 `error.md` 전체를 확인했다. 현재 버전의 `retry()`는 재조회·재렌더링을 수행하지만 `reset()`은 재조회 없이 오류 상태를 초기화한다.
- 공개 루트/Works/Crew 오류 화면과 루트 레이아웃 바깥 global-error의 “다시 시도”를 실제 `retry`에 연결했다. 같은 버튼·문구·스타일을 유지하며 새 UI는 만들지 않았다.
- 오류 값은 `unknown`으로 받아 원문을 화면에 표시하지 않는다. 홈 이동도 유지한다. 관리자 편집 화면의 복구·이동 보호 코드는 바꾸지 않았다.
- 기준 문서: 설치본 `03-file-conventions/error.md`, `04-functions/unstable_rethrow.md`.

## 검증

- 새 테스트 **88개**: 실제 네 목록/Works 메타데이터에 SDK 응답을 주입하는 서버 연결 80개, 공개 오류 화면의 retry 연결·원문 비노출·홈 이동·문서 구조 8개.
- 서버 입력 테스트에서 수정 전 62개 실패를 확인하고 수정 후 모두 통과했다. 이는 서로 다른 오류 증상과 분류 검사를 포함하며, 실제 운영 장애 62건을 뜻하지 않는다.
- SDK 조회·오류 보고와 하위 화면만 대체한다. 실제 서버 페이지, 공통 입력 판별, 기존 Studio merge/예비값 정책은 실행한다. 오류 버튼 검사는 실제 DOM 클릭과 Next가 제공하는 콜백의 연결을 확인한다.
- 전체 **4,959개 / 117개 파일**, 타입 검사·ESLint·프로덕션 빌드 통과. 공개 1시간 ISR·기존 상세 사전 생성과 사이트맵 설정은 유지됐다.
- 로컬 프로덕션 스모크 **41/41 통과**. 네 목록의 실제 HTML도 각각 200·기존 페이지 제목을 확인했다. 빌드와 로컬 서버 출력에 새 입력 검증/Studio 대체 오류 보고는 없었다. 임시 서버는 종료했다.

## 범위와 한계

- 화면이 사용하는 자료형에 대한 방어다. 모든 CMS 스키마·사업상 필수값·의미 검증을 다시 구현하지 않았고, 사용하지 않는 추가 필드나 상세 본문 전체를 변환하지 않는다. 임의 Proxy/getter를 안전하게 실행하는 격리 환경도 아니다.
- Studio의 예비값은 과거 설정 데이터이며 최신 가격을 보장하지 않는다. 이번에 예비값을 폐지하거나 방문자용 장애 안내를 추가하지 않았다. 이를 더 엄격하게 운영하려면 별도 정책을 정해야 한다.
- 빈 정상 목록과 다른 오류는 구분하지만, 원본/네트워크 문제가 계속되면 retry만으로 복구되지 않는다. 실제 CMS 장애를 유발한 브라우저 종단 복구 검증은 하지 않았다.
- 데이터 목록과 Next 콜백 계약을 모의 검증한 것이며 운영 문서를 망가뜨리거나 실제 비공개 항목을 저장해 시험하지 않았다.
- 운영 저장·업로드·환경변수·의존성·스키마·디자인 변경·커밋·배포는 하지 않았다.
